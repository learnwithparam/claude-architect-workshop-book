      The context budget

      Window minus output minus thinking is your room

      A Lumen Supply agent fails with a context error on a 60-turn refund case, so a developer raises max_tokens. The error comes back with a larger overage, because output and thinking take their room from the same window as the history. This lesson budgets the room, trims on a rule, and keeps the case facts in a state object. The case is 60 turns long and holds 26,982 tokens of history. The window is fixed, and input, output and thinking all share it. You will count the tokens before the call, see what a raised output limit costs, and write the two functions that fix it.

      I doWatch the failure and its fix.

      One 60-turn case and a fixed window

      The model reads only what fits in its window. Your code decides what goes in, so your code does the budget: it counts the input, reserves the output and thinking, and trims the rest.

      Three things go wrong, in this order. The output limit is raised to fix a context error, which leaves less room. The history is never trimmed, so long cases always overflow. And the case facts live only in the history, so a trim deletes them.

      The room formula, written as code

      The room for input is the window minus the output limit minus the thinking budget. Thinking tokens count toward the window, so a thinking budget is not free. The API spends them from the output limit. This lab reserves them as a line of their own on top, which can only reserve more than a call uses.

      compact then keeps the newest turns that fit in 80 percent of the room. The other 20 percent is margin, because a count is exact only for the request you counted.

      A turn that states a case fact carries it in a facts key, such as the order number. compact merges those keys into the state object.

      Budget, compact and keep a state object

      room subtracts the output limit and the thinking budget from the window. compact keeps the newest turns that fit in 80 percent of that room. It also collects the facts from every turn into a state object.

      The state object is sent in the system prompt, outside the part that is trimmed. A trim can then drop any turn without losing a fact. Sending a 27,000-token history on each of 60 turns costs $1.62 of input on Haiku, and the compacted 16,237 tokens cost $0.97.

      Count before you call

      The token count is a real API call that returns the input size before you send. The lab counts the full history once and uses that number to size each turn. It then counts the request it plans to send, and sends it only if input, output and thinking fit the window.

      The same budget covers what enters the history. Rank retrieved passages and send the top few, and cut a tool result to the fields the next step needs before it is stored. Cache the unchanging prefix. Each of these cuts input tokens, which are billed on every call.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A refund agent fails with a context error on 60-turn cases. The window is 40,000 tokens, the history is 27,000 tokens, and 2,000 tokens are reserved for thinking. A developer raised max_tokens from 1,024 to 16,000 to stop the error, and the next run failed with a larger overage. Which change addresses the cause?

      1. ARaise max_tokens again to 32,000, so replies are not cut off and the error cannot return.
      2. BTrim the history so input, output and thinking fit the window, and keep max_tokens modest.
      3. CRemove the thinking budget and keep max_tokens at 16,000, since thinking is the only part that shares the window.
      4. DMove to a larger window tier and leave the history growing, since the window then cannot overflow.
      Show the answer

      Answer: B

      • A Output shares the window with input. A larger limit takes room from the history, so the error comes sooner.
      • B Correct. The room is the window minus output minus thinking, so the history has to fit inside what is left.
      • C Thinking tokens count toward the window like any others. Removing the budget frees room, but the raised output limit still leaves too little.
      • D A larger window moves the limit and the history keeps growing each turn, so the error returns later.

      2. A planning agent runs in a window of 200,000 tokens. It reserves 8,000 tokens for its answer and 16,000 tokens for thinking, and neither can be lowered. The case history is 190,000 tokens, and a teammate says it fits because the window is larger than the history. What is the room for input, and what follows?

      1. AThe room is 200,000 tokens, so the history fits with 10,000 to spare.
      2. BThe room is 192,000 tokens, so it fits with 2,000 to spare after the answer reserve.
      3. CThe room is 176,000 tokens, so the history is 14,000 over and must be trimmed.
      4. DThe room is 184,000 tokens, so the history is 6,000 over and only the answer reserve needs lowering.
      Show the answer

      Answer: C

      • A The window is the total, not the room. The answer and thinking reserves are taken from it first.
      • B That subtracts the answer reserve and forgets the thinking reserve, which is also taken from the window.
      • C Correct. 200,000 minus 8,000 minus 16,000 is 176,000, and the history is 14,000 over that.
      • D That subtracts only the thinking reserve and forgets the answer reserve. The room is 176,000, and the trim is larger.

      3. A 60-turn refund case is trimmed to its newest 36 turns to fit the window. The refund amount was agreed in turn 3, so it was trimmed away, and the closing answer now asks the customer for it again. The fix must keep the amount and must not send more tokens than the room allows. Which design keeps the amount?

      1. AKeep the facts in a state object sent with every request, outside the part that is trimmed.
      2. BTrim the newest turns first, so the early turns and their facts survive the trim.
      3. CAdd a summary of the dropped turns as one more turn in the history, and let the next trim treat it like any other.
      4. DTrim at 100 percent of the room, so there is no margin and the early turns are more likely to stay.
      Show the answer

      Answer: A

      • A Correct. The state object carries the facts, so a trim can drop any turn without losing them.
      • B Dropping the newest turns loses the latest instructions, and the closing answer depends on those.
      • C A fact kept only in the history is deleted by the next trim. The state object must live outside it.
      • D Compaction keeps the newest turns that fit, so the oldest go first at any share. A trim at 100 percent only removes the margin.

      4. A review of a failing agent lists everything that shares its 40,000-token window. The agent sends a 27,000-token history, a short system prompt and one closing question, and the review must say what else reduces the room left for input. Select two items that take room from the input.

      1. AThe price per million input tokens, which is set by the model.
      2. BThe output limit set with max_tokens, which is reserved before the call.
      3. CThe temperature setting, which changes how varied the replies are.
      4. DThe thinking budget reserved for the reply, which counts toward the window.
      Show the answer

      Answer: B, D

      • A Price is a cost, not a share of the window. It does not change how many tokens fit.
      • B Correct. Output tokens are reserved from the same window, so a larger limit leaves less for input.
      • C Temperature changes how the reply varies, not how much of the window it takes.
      • D Correct. Thinking tokens count toward the window and the output limit, so they take room too.

      5. A retrieval step returns 40 passages of about 700 tokens each, which is 28,000 tokens. The window is 32,000 tokens with 4,000 reserved for output and 2,000 for thinking, and neither the window nor the cost per call can grow. The step must send its input inside 80 percent of the room. Which change fits the budget?

      1. ASend the first 20 passages in the order they were retrieved, and drop the other 20 without a ranking.
      2. BRaise max_tokens so the answer can cite more of the 40 passages in its reply.
      3. CSend all 40 passages and ask the model to ignore the ones it does not need.
      4. DRank the passages by relevance and send the top ten ahead of the question.
      Show the answer

      Answer: D

      • A Fourteen thousand tokens fit, but the order retrieved is not the order of relevance, so the best passages may be dropped.
      • B A larger output limit takes room from the input, so fewer passages fit.
      • C Ignored passages still take room and cost, and the request overflows at 28,000 tokens against a room of 26,000.
      • D Correct. Ten passages are about 7,000 tokens, which is inside 80 percent of the 26,000-token room, and they are the relevant ones.

      6. A team chose a window five times larger so that it never has to trim a case history. The history now grows to 100,000 tokens, each call re-sends all of it, and the cost per call rose fivefold while the accuracy bar did not move. The budget is fixed. Which change is right?

      1. ATrim old turns and keep the facts in a state object, so each call sends only what the step needs.
      2. BKeep the large window and ask for shorter answers, since output is where the cost sits in this setup.
      3. CRaise the output limit to use the extra window, so each call does more work for the same price.
      4. DCompact only when the history reaches 100 percent of the room, so fewer calls pay for compaction.
      Show the answer

      Answer: A

      • A Correct. Input tokens are billed on every call, so sending less is the lever. A larger window only moves the overflow.
      • B The cost grew because the input grew. Shorter answers cut the small part of the bill.
      • C A larger output limit takes room from the input and adds spend. It does not fix the re-sent history.
      • D Compacting at 100 percent leaves no margin and the request fails first. A trim at about 80 percent keeps the call safe.

      7. An agent calls a lookup tool that returns a 20 KB record, about 5,700 tokens, on every call. After six calls the 40,000-token window is full, and the next step needs only the order status and the carrier from each record. Which change keeps the loop running?

      1. ARaise max_tokens so the later calls have more room to finish their replies.
      2. BMove to a larger window and keep every full record in the history for later calls.
      3. CCut each tool result to the fields the next step needs before it is stored.
      4. DKeep every full record and drop the oldest turns only when the context error appears.
      Show the answer

      Answer: C

      • A A larger output limit takes room from the input, so the window fills sooner.
      • B A larger window only delays the overflow, and each full record is billed on every later call.
      • C Correct. Two fields are a few dozen tokens, so six calls use almost none of the window.
      • D Waiting for the error drops turns after the failed call, and the dropped turns may hold facts the case needs.

      8. A support agent re-sends its whole history on every turn, and the input bill grows with each turn of a 60-turn case. The agent must keep the case facts and must not lower its accuracy. Select two changes that cut the cost of the re-sent history.

      1. ACompact old turns into a short block, and keep the facts in a state object.
      2. BRe-send the whole history on every turn, so the model never misses a fact.
      3. CCache the stable prefix, such as the system prompt and the tool list, so it bills at the cached rate.
      4. DPick a window ten times larger, so the history is billed once and not on every turn.
      Show the answer

      Answer: A, C

      • A Correct. Fewer tokens per call is the direct cut, and the state object keeps the facts.
      • B Re-sending everything is the cost. Facts belong in a state object, not in a growing history.
      • C Correct. The unchanging prefix is the same on every call, so caching it cuts its price.
      • D Every call still bills its input tokens, whatever the window size. A larger window does not bill once.

      Conclusions

      • Room is the window minus the output limit minus the thinking budget, and the history must fit inside it.
      • Count the tokens before the call, trim at about 80 percent of the room, and never raise max_tokens to fix a context error.
      • Keep the case facts in a state object outside the trimmed history, so a trim never deletes one.

      count_tokens

      An API call that returns the input size of a request before it is sent

      Compaction

      Dropping the oldest turns until the history fits a share of the room

      The tokens reserved for the model to think, which count toward the window
