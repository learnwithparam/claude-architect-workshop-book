      Review criteria

      Name what counts, then review one file at a time

      A Lumen Supply release changes many files. A review told to be thorough reads them all in one request, flags files that are fine, and buries the real bugs. The team stops reading the comments. This is the review bot at Lumen Supply, an online electronics shop. You will watch it drown its own findings, then fix it with named criteria and one pass per file.

      Say what counts, then look at one file at a time

      A review has two parts you control. The criteria say what to report and what to skip. The passes say which files go into which request. The code splits the files, and the model reviews each one.

      Three things go wrong. Being thorough flags style noise and real bugs alike. One pass over many files spreads attention thin. A fault between two files has no pass that looks for it.

      Write criteria with examples, and split the passes

      The criteria now say to report a wrong result and to skip style, names, notes and magic numbers. Each line starts with Report or Skip and gives a small example.

      The passes return one request per file, then a last request over all the files. A category that flags too many clean files is switched off until its criteria are fixed.

      The recorded criteria are short. A harder review adds more, and each addition has a job:

      • Define each severity level by what puts a finding there, and show one finding at the level. A bare word such as high leaves the boundary to the model, and two runs can draw it differently.
      • Show the output format in an example, with the file, the issue, the severity and the fix. A review that comes back in five shapes cannot be read by a pipeline.
      • Give two to four examples that cover the ambiguous cases, and the reason each is right or wrong. The reason lets the model carry the rule to a new case. A long pile of examples costs tokens on every call.
      • For extraction, show documents in different layouts, including one where a field is missing, so a missing field stays empty and is not invented.

      A fixed chain, or an adaptive plan

      The arrows show files going in and flags coming out. A release review has known steps, so the code runs them as a fixed chain: one pass per file, then the pass across files. Nothing is decided by the model about which step comes next.

      An open investigation is different. Its next step depends on what the last one found, so it uses an adaptive plan. Map the structure first, then plan the work by priority.

      Measure by type before you automate

      The result line of this run keeps two counts apart, the bug files flagged and the clean files flagged. One total would hide that. A job that is right 97 times in 100 may be wrong on 4 in 10 of one kind of form. Break accuracy down by type and by field.

      Sample the output at random from each group. A labelled set is a batch of outputs a person has marked right or wrong. Use one to set a confidence cutoff for each field, the score below which an item goes to a person, and send unclear items there too.

      A review that posts too many findings can add a verification pass. That is a second request that reads each finding again and attaches a confidence, a number for how sure it is. Route by that number only after checking it against labelled findings, because a score the model gives itself is not a measure.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A review bot posts comments on 9 of 14 files, and 6 of those files are fine. The team has started to ignore the bot. What is the root fix?

      1. ATell it to be more thorough, so it finds the bugs among the noise.
      2. BName which problems to report and which to skip in the criteria.
      3. CAsk it for a longer report, so each comment carries more detail.
      4. DLower the severity of every comment so nobody is alarmed by them.
      Show the answer

      Answer: B

      • A A plea for thoroughness names no category, so style noise counts as much as a bug.
      • B Correct. Explicit criteria separate a wrong result from a matter of taste.
      • C A longer report gives the reader more to skip. It does not change what gets flagged.
      • D A softer label keeps the noise and makes the real bugs easier to miss.

      2. The prompt already says to be conservative and only flag what matters. Even so, 60 percent of the flags on a release are noise. What works better?

      1. AWrite conservative in capitals, so the instruction carries more weight.
      2. BAsk the model to flag only when it is certain, and trust its answer.
      3. CSend the review to a model with a larger window, so it sees more.
      4. DName the categories that count, with a sample of each.
      Show the answer

      Answer: D

      • A Volume does not define the word. The model still has no list of what matters.
      • B Stated certainty is not a measure, and a wrong flag can sound as sure as a right one.
      • C A larger window holds more text. It gives no rule for what to report.
      • D Correct. Named categories tell the reviewer where the line is, and a sample shows it.

      3. One review category flags 8 false positives in every 10 comments. The team now distrusts the other categories too. What should you do?

      1. AKeep it on, because a noisy category still finds some real problems.
      2. BRaise the severity of the other categories so they stand out from it.
      3. CTurn that category off until it is fixed, and keep the rest.
      4. DTurn the whole review off until every category is accurate.
      Show the answer

      Answer: C

      • A The real problems it finds are lost among the false ones, and readers stop looking.
      • B Louder labels do not remove the noise. The reader still sifts the noisy category.
      • C Correct. One noisy category costs the trust in all of them, so switch it off until it is fixed.
      • D This throws away the categories that work, along with the one that does not.

      4. Select two things that make a severity level usable in a review prompt.

      1. AA definition of when each level applies.
      2. BA single word for each level, such as high or low.
      3. CA short code example that shows each level.
      4. DA sentence that asks the reviewer to use good judgement.

      Answer: A, C

      • A Correct. A definition says what puts a finding at that level.
      • B A bare word leaves the boundary to the model, so two runs can split it differently.
      • C Correct. An example shows a finding at the level, so the line is concrete.
      • D Judgement with no rule is the gap the criteria are meant to fill.

      5. Across 10 runs, a review comes back in 5 different shapes, and the pipeline cannot read half of them. What is the fix?

      1. AShow the format in examples: file, issue, severity, fix.
      2. BRun it again each time until the shape matches what the parser wants.
      3. CWrite in the prompt that the format must be followed strictly.
      4. DAdd 12 more examples of findings, so the shape is averaged out.

      Answer: A

      • A Correct. An example of the exact format is the clearest way to fix the shape.
      • B Each rerun costs a call and still may not match.
      • C A stern line names no shape. The model still has to guess one.
      • D More examples raise the cost, and a long pile can pull the output toward the wrong one.

      6. A print call in a demo helper is fine, but the review flags it in every run. How do you stop that without hiding real problems?

      1. ALet it flag the print call, and have a person drop it each time.
      2. BAdd an example of the print call as acceptable, with the reason.

      • B Correct. An acceptable pattern with its reason settles an ambiguous case.
      • C The call is still flagged, only under different words. The judgement was never made.
      • D Without examples the model has even less to go on.

      7. An extraction job invents a value for a field when the document has none. The documents come in 4 different layouts. What helps most?

      2. BName every field in the prompt and add nothing else to the instructions.

      • D A lower temperature makes the model more repeatable, and it can repeat an invented value.

      11. A review posts findings that a person must read, and there are far too many to read. How should they be routed?

      1. APost the ones that sound the most certain first, and trust the order they come in.
      2. BAdd a verification pass, calibrated on labelled findings, and route by its score.
      3. CPost every finding in one list, and let each reader sort the list by hand.
      4. DPost the average accuracy of the whole review next to the list of findings.
      Show the answer

      Answer: B

      • A Tone is not a measure, and a wrong finding can sound sure. A score needs checking against labels.
      • B Correct. A second look attaches a confidence, and calibrating it on labelled findings makes it usable for routing.
      • C One list sends the noise to the person along with the signal.
      • D An average does not say which findings to read first.

      12. Select two reasons to add a review pass that is separate from the pass that wrote the code.

      1. AIt has no memory of how the code was written, so nothing anchors it.
      2. BIt remembers the bugs from earlier runs and looks for them first.
      3. CIt reruns the same check, so a bug is confirmed by two identical answers.
      4. DIt can read across files, which a pass on one file cannot do.
      Show the answer

      Answer: A, D

      • A Correct. A fresh instance starts with none of the author's reasoning.
      • B An instance carries nothing from earlier runs.
      • C An identical rerun adds nothing. The value is in the different view.
      • D Correct. A pass that holds several files can see how they fit together.

      13. A release review always takes the same steps over 14 files, in the same order. How should you build it?

      1. AAs an open plan that the model redraws after every file.
      2. BAs an adaptive plan, because adapting is always safer.
      3. CAs one step, because fewer steps always means fewer errors.
      4. DAs a fixed chain of passes that the code runs in order.
      Show the answer

      Answer: D

      • A An open plan spends calls deciding what the code already knows.
      • B Adapting helps when the steps are not known, and here they are.
      • C Fewer steps here means one pass over 14 files, which is the failure.
      • D Correct. A predictable job is a fixed chain, which is easy to test and to repeat.

      14. An investigation of an unfamiliar code base keeps turning up modules nobody expected. How should the work be planned?

      1. AAs a fixed chain written before the work starts.
      2. BBy reading every file in the repository before doing anything else.
      3. CAs an adaptive plan that is revised as each finding comes in.
      4. DBy writing the full plan up front and never changing it.
      Show the answer

      Answer: C

      • A A fixed chain cannot follow modules it did not know about.
      • B This is slow and it fills the context before the work has begun.
      • C Correct. When each step depends on what the last one found, the plan has to adapt.
      • D A plan that never changes cannot follow what the work turns up.

      15. A chain reviews each of 14 files alone, and nobody checks how the files call each other. What should be added?

      1. AA last pass over all the files, reading the links.
      2. BNothing, because each file was checked in full.
      3. CA bigger context window on each single-file pass, so it sees more.
      4. DFold every file into one pass, so the links are visible.
      Show the answer

      Answer: A

      • A Correct. The integration pass reads the calls across files that no single pass sees.
      • B Checking each file in full does not check how two files fit together.
      • C A single-file pass still holds one file, however large its window.
      • D This brings back the dilution the per-file passes removed.

      16. Select two steps that start an adaptive plan for an unfamiliar project.

      1. ARead every file in full before forming any plan.
      2. BMap the structure of the project first.
      3. CPlan the work by priority, from what the map shows.
      4. DFix the order of all the steps before looking at the code.
      Show the answer

      Answer: B, C

      • A This fills the context with files that may not matter.
      • B Correct. A map shows where the code lives at a low cost.
      • C Correct. The map says which areas matter, so the work starts there.
      • D An order fixed in advance cannot respond to what the map shows.

      17. An extraction job scores 97 percent overall, but one of its 6 form types scores 61 percent. What should you do before automating it?

      1. AAutomate it, since 97 percent is above the bar.
      2. BTest more of the form types that already pass.
      3. CRaise the pass mark to 98 percent and stop there.
      4. DBreak accuracy down by form type and field.
      Show the answer

      Answer: D

      • A The 97 percent hides a form type that fails 4 times in 10.
      • B More passing forms make the average look better and hide the weak one.
      • C A higher mark says nothing about which form type fails.
      • D Correct. An average hides a weak type, and the breakdown shows it.

      18. The extractions marked high confidence are not reviewed. A check of 100 of them finds 4 wrong. How should such output be sampled?

      1. AIt needs no sampling, because high confidence means correct.
      2. BSample at random from each confidence and type group.
      3. CRead the first 100 that arrive each day.
      4. DSample only the low-confidence ones, since they are the risky ones.
      Show the answer

      Answer: B

      • A Four in a hundred were wrong, so high confidence does not mean correct.
      • B Correct. A stratified random sample shows the error rate in each group.
      • C The first 100 are not random, and they may all be one type.
      • D This leaves the high-confidence group, where the wrong answers were found, unchecked.

      19. The team sets the confidence cutoff for each field by feel, and the cutoffs keep drifting. What makes them stable?

      1. ACalibrate each cutoff on a set of labelled documents.
      2. BTrust the model's own score, since it knows how sure it is.
      3. CKeep the cutoffs by feel, and revisit them each week.
      4. DUse one cutoff for every field, so there is nothing to drift.
      Show the answer

      Answer: A

      • A Correct. Labelled documents show how often each score is right, so a cutoff can follow.
      • B A model's score is not calibrated to the truth until it is checked against labels.
      • C This is the drift. A cutoff should be set from data.
      • D Fields differ in how hard they are, so one cutoff is wrong for most of them.

      20. Select two kinds of extraction that should go to a person.

      1. AEvery extraction, because a person must see them all.
      2. BAnything from a source the model has read before.
      3. CLow confidence on a field.
      4. DA source that is unclear or contradicts itself.
      Show the answer

      Answer: C, D

      • A This removes the value of automating. Reserve a person for the cases that need one.
      • B A familiar source can still be wrong, and being familiar is not a reason to skip a check.
      • C Correct. Low confidence is the signal that a person should check the value.
      • D Correct. Where the source is unclear the model cannot be checked against it.
