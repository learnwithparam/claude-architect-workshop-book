      Foundations, lesson 1

      The agent loop

      An agent is a loop that ends on stop_reason

      Your support agent needs four tool calls to refund one order. Its loop stops when the reply says done, or after three turns. So the refund never runs, and nothing reports that work was left. This is the agent at Lumen Supply, an online electronics shop. You will watch the loop fail, then fix it so the API decides when the work is over.

      I doWatch the failure and its fix.

      One loop, four tools, one refund

      The loop is the code around Claude. It sends the system prompt and the history, runs the tools Claude asks for, and sends the results back. Claude decides, the loop runs, and only code can guarantee anything. The history holds three kinds of turn: user, assistant and tool_result.

      A refund needs four tools in a fixed order: get_customer takes the email, lookup_order takes the customer id, check_return_window takes the order, and process_refund pays. The next tool depends on the last result, so the plan adapts as results arrive.

      Four calls in a row end in a refund

      Each card is one tool call; open it to read it field by field. Every reply carries a stop_reason, the field that says why Claude stopped. Here it is tool_use, which means Claude wants a tool run, and the tool_use block carries an id, a name and an input. The loop answers with a tool_result block that repeats that id.

      The loop stopped only when Claude stopped asking. Nothing counted turns and nothing read the words.

      The stop rule is a few lines

      This loop decides from the words in the reply. If Claude writes "done", it stops, and it never runs more than three turns. Text is not a signal: a customer can ask for it, and Claude can write it early.

      Every turn also resends the whole history, so each request is longer than the last. A five-turn refund sends 1, 3, 5, 7 and 9 messages.

      The loop reads stop_reason

      Every reply carries a stop_reason. It is tool_use when Claude wants a tool and end_turn when it is finished. With these four client tools, the fixed loop continues on tool_use and stops on anything else, including max_tokens and stop_sequence. A server tool can also return pause_turn, which the loop must send back to continue.

      The turn cap stays as a backstop, now 10. Every tool_use id gets a tool_result in the next user turn. A result with no matching tool_use returns a 400, and so does dropping a block from an assistant turn.

      The Agent SDK runs the loop for you

      The Claude Agent SDK is your loop with the hand-written part removed. query calls Claude, runs each tool and stops on its own. max_turns is the backstop. The refund ticket takes five turns: four tool calls and a final reply. Claude picks each next tool from the last result. This is a real Claude Haiku 5.5 run.

      Claude picks each step from the last result, so the plan adapts. It maps the task, works by priority and adds steps as findings turn up.

      A chain is the other shape: the same fixed steps in order, which suits a monthly review. Each step gives its output a check, and a final pass catches what spans steps. A chain loses any lead it has no step for, so an open investigation needs the adaptive plan.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A support loop handles 200 tickets. On 41 of them Claude returns stop_reason tool_use after the customer lookup and the refund call is still to come. Which rule decides whether the loop goes round again?

      1. AA sentence in the system prompt telling Claude to say when it is finished.
      2. BContinue while stop_reason is tool_use, and stop on any other value.
      3. CCount the turns and stop once the count reaches the cap.
      4. DStop as soon as the reply text reads like a finished answer.
      Show the answer

      Answer: B

      • A A prompt sentence changes what Claude writes, not what the loop does. The loop still needs its own rule.
      • B Correct. stop_reason is the field the API sets to say Claude is waiting for tool results.
      • C A cap is a backstop for runaway loops. As the main rule it cuts tickets that still have work left.
      • D Reading the text lets the wording of a reply decide the flow, which is how narrated turns end early.

      2. The loop caps a ticket at 3 turns. A refund ticket needs get_customer, lookup_order, check_return_window and process_refund, which is 4 calls. On 41 of 200 tickets the run ends with no reply. What is the fix?

      1. ARaise the cap to 4, which covers exactly the tickets seen so far.
      2. BStop on the first reply that contains text, so the cap is never reached.
      3. CKeep stop_reason as the rule, with a cap far above any normal ticket.
      4. DRemove the cap, because stop_reason already ends every run.
      Show the answer

      Answer: C

      • A A cap set to the longest ticket seen fails on the next ticket that is one call longer.
      • B Text is often written beside a tool request, so this ends runs with the refund still unpaid.
      • C Correct. The rule ends normal runs, and the cap only catches a run that never ends.
      • D A run that keeps asking for tools would loop until the bill stops it. The backstop is cheap insurance.

      3. To save tokens a developer skips the tool_result for a lookup whose output was empty. The next request returns a 400. Why?

      1. AEvery tool_use id must be answered by a tool_result in the next user message.
      2. BEmpty results are dropped by the API, so the request is missing a field.
      3. CTool results belong in the assistant turn, next to the tool_use block.
      4. DThe request hit a rate limit, and sending it again will succeed.
      Show the answer

      Answer: A

      • A Correct. The history is checked on every call, and an unanswered tool_use makes it invalid.
      • B Nothing is dropped. An empty result is still a block the loop must send, for example with text saying no rows.
      • C Results go in a user message that follows the assistant turn. Claude never writes them.
      • D A 400 means the request is malformed. Sending the same history again returns the same error.

      4. Select two statements about stop_reason that a loop should rely on.

      1. Aend_turn means Claude has finished and the loop can return the reply.
      2. Bmax_tokens means Claude finished its answer within the limit.
      3. Cmax_tokens means the reply was cut off, so the loop must not treat it as complete.
      4. Dtool_use means the loop must wait for the customer to approve the tool.
      Show the answer

      Answer: A, C

      • A Correct. end_turn is the normal finish with nothing left to run.
      • B max_tokens is the opposite of finished. The reply stopped at the limit, possibly in mid sentence.
      • C Correct. A cut reply is partial, so the loop raises the limit or reports it.
      • D The loop runs the tool itself and sends the result back. The customer is not asked.

      5. A 14-file change is reviewed in one pass. The review misses a bug where file 3 sends a field that file 11 no longer reads. What review design catches it?

      1. AKeep the single pass, because one careful read sees the whole change.
      2. BAsk for a shorter change, since large diffs are where bugs live.
      3. CRun the same single pass three times and merge the comments.
      4. DReview each file alone, then run a pass on how the files connect.
      Show the answer

      Answer: D

      • A Attention thins across 14 files. A single read misses what sits far apart.
      • B Smaller changes help, but the review design still has to handle the change in front of it.
      • C Repeating the same pass repeats the same blind spot. The design has to change.
      • D Correct. Per-file passes find local bugs, and the link pass finds cross-file ones.

      6. An open investigation uses a fixed 5-step chain. At step 2 the agent finds a lead the chain has no step for, and it is lost. What should change?

      1. AAdd more steps to the chain so it covers the lead next time.
      2. BLet Claude adapt the plan as findings arrive, inside the loop.
      3. CHave the code pick the next tool from a list of rules.
      4. DRun all five steps at once so none waits on another.
      Show the answer

      Answer: B

      • A A longer chain still cannot cover a lead nobody predicted.
      • B Correct. When the next step depends on what was found, the plan has to be chosen by Claude as it goes.
      • C Code rules are a fixed chain in a different form. They miss the same unforeseen lead.
      • D The steps depend on each other, so running them at once breaks the order.

      7. A monthly review has the same 4 steps every time, and the output feeds an audit. Which pattern fits?

      1. AAn adaptive plan, because it copes with any input.
      2. BOne prompt that does all four steps in a single pass.
      3. CPrompt chaining with a final pass that checks the results together.
      4. DAn open loop, because it is more reliable than fixed steps.
      Show the answer

      Answer: C

      • A Adaptive plans suit unknown work. Fixed work gains nothing from them and gets less predictable.
      • B One pass is where steps get skipped or blurred, and there is no place to check each one.
      • C Correct. Fixed steps are predictable and each output can be checked. The last pass joins them.
      • D An open loop varies from run to run, which is a cost when an audit needs the same steps.

      8. Select two facts about an adaptive investigation plan.

      1. AAll subtasks are listed before any file is read and stay unchanged.
      2. BIt maps the structure first and plans the work by priority.
      3. CCode chooses the next tool from a table of rules.
      4. DNew subtasks are added as findings turn up.
      Show the answer

      Answer: B, D

      • A A list fixed up front is a chain. The point of adapting is that the list grows.
      • B Correct. A map shows where the risk is, so the highest priority work goes first.
      • C Choosing the tool is left to Claude each turn. A rule table removes the adaptation.
      • D Correct. A finding can open a subtask nobody listed, and the plan takes it in.

      Conclusions

      • The loop follows stop_reason: tool_use means run the tools and ask again, and end_turn means finished.
      • Every tool_use gets a tool_result in the next request, or the request fails.
      • A turn cap is a backstop against a runaway loop, never the stop rule.

      tool_use

      A limit on loop turns that guards against a runaway loop
