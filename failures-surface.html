      Surfacing failures

      A failed search must reach the report

      A coordinator starts three researchers to search the recall notes, then a writer drafts the report. The regulator search times out and the merge drops it, so the report reads as complete and a whole section is missing. A reader trusts it. This is the agent at Lumen Supply, an online electronics shop. You will watch a failure vanish, then fix the record and the merge so the report names what was not covered.

      I doWatch the failure and its fix.

      A failure is a result the writer must see

      Researchers search and report back. A search can fail in two ways: it times out, or it half works. Two sources that disagree are not a failure, but both figures must stay in the report. The researcher classifies the failure, the coordinator decides what to do and the writer says what is solid and what is not.

      This design goes wrong in three ways. A timeout is swallowed, one failure aborts every angle, and a merge picks one of two conflicting figures. You will see the first fail, then fix it, then see the third.

      A failure that travels gives an honest report

      The coordinator starts three researchers with the Agent tool, called Task in older releases, one for each group of searches. The regulator search fails, and its result comes back with an error flag and a category. The harness reads that result as the researcher got it, and your failure and merge turn it into a line the writer reads.

      CLAIMED_COMPLETE.
      Keep the kind, the query and what came back
      The fix gives a failure a record with four fields: the kind, the query, the attempt and the partial results. The merge writes a line for each failed search and tells the writer not to call the report complete. A transient failure is retried once where it happens, and only the rest is passed up.
      

      An empty result is different. A search that ran and found nothing is a valid answer. Only a search that could not be done is a failure.
      

      A gap can also start in the plan. An angle nobody owns is never searched, so the report has an empty section and no failure to show for it. Broaden the split so every topic has a researcher, instead of retrying the same narrow plan.

      Errors need a category
      A tool that fails with only "Operation failed" gives the researcher nothing to report. In the bare run the regulator researcher passes on just those two words. Switch to the run where the error carries a category, a retry flag, a message, the attempt and the partial results. There the researcher reports a timeout that cannot be retried.
      

      An MCP tool, one served through the Model Context Protocol, sets isError on its result and puts the errorCategory in the content. A business rule that rejects a request is not retryable, and the error should say why, so the agent stops instead of retrying.
      

      The writer should also mark how well the merged report is supported. Mark the claims that their sources support well, apart from the ones sources dispute, and show the sources of each dispute. Mark every gap where a search failed or no source was found, and never hide one inside the conclusion.

      Check your understanding
      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.
      

      1. A regulator search times out. The merge drops that angle, and the writer produces a report that reads as complete. 1 of 4 angles is missing. What is the root fix?
      1. AAsk the writer to sound less certain in the conclusion, since one of the four angles may be thin.
      2. BPass the failure to the writer with its kind and its query, so the report can name the gap.
      3. CAdd a second search for the regulator each time, so that a timeout becomes unlikely on the next run.
      4. DDrop the regulator angle from the plan for good, since its search is not reliable enough to keep.
      Show the answer
      Answer: B
      • A Hedged wording does not tell the reader which angle is missing or why.
      • B Correct. A failure that never reaches the writer cannot appear in the report, so it must travel as a result.
      • C A retry may help once, but a search that fails again is still dropped without a word.
      • D Removing an angle hides the gap instead of reporting it.
      2. A researcher times out on one of 4 searches. The coordinator aborts the whole run, so the 3 good results, about 75 percent of the work, are lost. What should happen instead?
      1. ARetry the whole run from the very start until all 4 searches pass in the same attempt.
      2. BKeep the abort, but add a clearer error message for the person who reads the log later.
      3. CSkip the failed search quietly and report the 3 results as if they were the whole answer.
      4. DReturn the failure together with the 3 good results, and let the report name the gap.
      Show the answer
      Answer: D
      • A A repeat of a failing search may time out again, and every pass throws away the good work.
      • B A better message does not save the 3 results that were lost.
      • C Skipping quietly hides the gap, which is the opposite mistake.
      • D Correct. Partial results still have value. The report can use them and say what is not covered.
      3. A subagent returns the string 'search unavailable'. The coordinator cannot tell whether to retry, try another source or stop. What should the subagent return?
      1. AThe kind of failure, what was tried, what came back before it failed and what to try next.
      2. BThe same string unchanged, since the coordinator can read it and judge for itself what it meant.
      3. CAn empty list, since no results were found and that is the honest answer to give here.
      4. DA longer sentence that says the search was unavailable for some unknown reason.
      Show the answer
      Answer: A
      • A Correct. A coordinator can decide only when it knows the kind, the query and the partial results.
      • B A bare message carries no kind and no query, so the coordinator is left guessing.
      • C An empty list looks like a valid search with no hits. A failure must not look like that.
      • D More words without a kind or a query still give the coordinator nothing to act on.
      4. Select two wrong ways to handle a failed search in a research run.
      1. APass the failure up with its kind, query and partial results.
      2. BDrop the failed angle from the merge and call the report complete.
      3. CRetry once where the failure is transient, then pass up what remains.
      4. DAbort every researcher because one of them failed.
      Show the answer
      Answer: B, D
      • A This is the right way, because the failure can reach the report.
      • B Correct. The reader is told nothing, so a missing section looks finished.
      • C A bounded retry is sound. Only an unbounded loop would be wrong.
      • D Correct. The good results are lost, and the coordinator learns nothing about what worked.
      5. Two sources give different failure rates for the same batch: 12 percent from a lab report and 15 percent from a claims desk. The merge keeps 15 percent. What is wrong?
      1. ANothing, since the higher figure is the safer one to report for a recall.
      2. BThe report should have averaged them to 13.5 percent, which is closer to the truth.
      3. CThe other figure and its source are gone, so the reader cannot see the conflict.
      4. DThe report is fine as long as it mentions that some sources were consulted.
      Show the answer
      Answer: C
      • A Safer is a judgement the reader should make with both figures in front of them.
      • B An average belongs to neither source and cannot be checked.
      • C Correct. Two figures from two sources are a finding. Keep both and say where each came from.
      • D A general note names no source, so the reader still cannot check anything.
      6. A report lists 40 swollen units from a 9 March field report and 65 from an 18 March claims update. A reviewer calls it a contradiction. What explains it?
      1. AThe dates differ, so the later count may include units that swelled after the first.
      2. BOne source is wrong, so the writer should keep the newer figure and delete the other.
      3. CBoth figures are noise, so the writer should report only that some units swelled.
      4. DThe claims desk counted the same units twice, so its figure should be halved.
      Show the answer
      Answer: A
      • A Correct. A date often explains a gap, and only a report that shows both dates lets the reader see it.
      • B Nothing says either count is wrong. Deleting one throws away the trend.
      • C Dropping both loses the evidence the reader needs.
      • D That is a guess with no source. The report should show the figures, not invent a fix.
      7. A synthesis of 14 findings mixes 11 settled claims with 3 that sources dispute. The reader cannot tell which is which. What should the writer do?
      1. AWrite all 14 in one list with the same wording, so the report reads evenly.
      2. BLeave out the 3 disputed claims, since a report should hold only what is certain.
      3. CPut the disputed claims first, since the reader should see the risks before anything else.
      4. DMark the settled claims and the disputed ones apart, and show the sources of each dispute.
      Show the answer
      Answer: D
      • A An even tone hides which claims are solid.
      • B Leaving them out hides the dispute, and a reader may need it.
      • C Order alone does not mark them as disputed or show the sources.
      • D Correct. A reader can weigh a disputed claim only when it is marked and its sources are shown.
      8. A report merges findings from 5 researchers. Select two rules for marking the quality of the synthesis.

      • D A uniform tone hides which claims are weak.
      9. A coordinator never heard that one of its 3 researchers failed. The researcher wrote the failure to its own notes. What does the design need?
      1. ALet researchers message each other directly, so a failure reaches whoever needs it without delay.
      2. BAll messages pass through the coordinator, so a failure is a message to it.

      Answer: B

      • B Correct. The coordinator is the one place that routes results and errors, so nothing can be lost on the side.
      • C The writer would read what was written, not what failed. The coordinator still would not know.
      • D A longer timeout reduces some failures. It cannot make the coordinator hear of the rest.

      11. A plan split a recall into 2 angles, and 2 topics have no owner. The report has two empty sections. What is the fix?

      12. A coordinator sits between 4 subagents. Select two things it owns.

      13. A tool returns the text 'operation failed' for 6 different faults. The agent cannot decide whether to retry. What should the tool return?
      1. AThe same text, since the agent can read it and judge which fault it was.
      2. BAn empty result, so the agent treats it as a search with no hits.

      14. A refund tool rejects a request under a business rule: the order is 90 days old and the limit is 30. The agent retries 5 times. What was missed?

      16. An MCP tool call fails. Select two things its result can carry.
