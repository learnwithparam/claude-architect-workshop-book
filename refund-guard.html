      The agent has one tool that moves money

      The Lumen Supply agent looks up customers, looks up orders, and refunds orders. It can also hand a ticket to a human. Only the refund tool moves money.

      You will put a precondition check in front of that tool. A precondition check is code that runs before a tool call and can refuse it. The model never sees the code. It sees a clear refusal it can act on.

      A precondition check runs before the tool

      The check sits between Claude and the tools, so every tool call passes through it first. For the refund tool it asks two questions: is the customer verified, and is the amount within the limit?

      When the answer is no, the check returns a refusal with a category, a retry hint and a plain message. The model reads the refusal and recovers.

      A refusal must say what to do next

      The check can refuse in two ways. A bare no says only that the refund is denied. A structured refusal adds a category, a retry hint and a message that names the missing step.

      Switch between them. After the bare no, the agent still hands the ticket to a human. It can only say the refund was declined with no reason, and the handoff says the same. After the structured refusal, it tells the customer that refunds over $500 need a human, and the handoff names the limit.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A support agent must never refund before verifying the customer. Logs show it skipped verification in 2 of 50 tickets even though the system prompt says to verify first. What is the most reliable fix?

      1. AMove the verification sentence to the top of the prompt and write it in capital letters.
      2. BDeny process_refund in the dispatcher until get_customer has succeeded.
      3. CAdd three worked examples of correct verification steps to the system prompt.
      4. DLower the temperature to zero so the model follows every instruction more closely.
      Show the answer

      Answer: B

      • A Emphasis raises the odds but is still a request. A 4% miss on a refund tool is still money moved without a check.
      • B Correct. A rule that must hold belongs in code that runs before the tool, and a structured denial lets the model recover.
      • C Examples help style and format. They do not guarantee a step happens on every ticket.
      • D Temperature changes variety, not obedience. The model can skip a step at any setting.

      2. A team enforces a $500 refund limit with a paragraph in the system prompt. A reviewer says this is a weakness. Which statement explains why?

      1. ALong prompts are truncated by the API, so the paragraph may not be read at all.
      2. BThe model cannot reliably understand numeric limits written in plain sentences.
      3. CA prompt is guidance, so nothing stops an over-limit call.
      4. DPrompts cost tokens on every single request, which makes the rule expensive to keep.
      Show the answer

      Answer: C

      • A Truncation is not the risk here. The paragraph is read and can still lose to a persuasive customer message.
      • B Models handle numbers well. Understanding is not the problem, enforcement is.
      • C Correct. A prompt shapes behaviour. A programmatic check refuses the call whatever the model decides.
      • D Cost is real but is not why a prompt-only limit fails a compliance review.

      3. Which two rules should be enforced in code instead of the prompt? Select two.

      1. ANo refund before the customer is verified.
      2. BKeep every reply under 120 words for readability.
      3. CA refund above $500 needs a human.
      4. DPrefer plain language over technical jargon.
      Show the answer

      Answer: A, C

      • A Correct. Skipping it has a financial and legal cost, so it must hold every time.
      • B Style rules fail softly. A long reply is a nuisance, not a breach.
      • C Correct. A money limit is a hard rule, so code refuses the call whatever the model decides.
      • D Tone guidance is a prompt job. There is nothing to enforce in code.

      4. The dispatcher denies process_refund because the customer is unverified. What should the denial return so the agent recovers on its own?

      1. AThe single word Error, which is short and clear.
      2. BAn empty result, so the model tries another approach on its own.
      3. CThe full stack trace from the failed check for debugging.
      4. DAn error with category, retryable flag and the step to take.
      Show the answer

      Answer: D

      • A A bare string gives the model nothing to act on, so it guesses or gives up.
      • B An empty result looks like success with no data. The model may report the refund as done.
      • C A stack trace leaks internals and does not say what to do next.
      • D Correct. Category, retryable and an action in the message let the model fix the cause and continue.

      5. A PreToolUse hook receives a process_refund call for $640, and the limit is $500. How does the hook stop the call?

      1. AIt edits the system prompt so the next turn avoids the call.
      2. BIt logs a warning and lets the call through for later review.
      3. CIt asks the model whether it is sure about the refund amount.
      4. DIt exits with a blocking status and a stderr message.
      Show the answer

      Answer: D

      • A The call is already made. A later prompt edit does not undo it.
      • B A warning after the fact means the money has moved.
      • C Asking the model to confirm puts the decision back in the model, which is the weakness the hook removes.
      • D Correct. A blocking exit stops the tool, and the message goes back to the model as the reason.

      6. Where should a hook that checks refund limits run?

      1. ABefore the tool executes.
      2. BAfter the tool returns, on the result.
      3. CAt the end of the session, over the whole transcript.
      4. DOnly when the user asks for a review.
      Show the answer

      Answer: A

      • A Correct. A pre-tool hook can refuse the call, so the money never moves.
      • B A post-tool hook can annotate a result but cannot undo the refund.
      • C An end-of-session check finds problems after they are done.
      • D A gate that depends on a request is not a gate.

      7. Intake routing already sends every ticket over $500 to a human. Why keep the refund limit in a hook too?

      1. AHooks make the model respond faster on every turn.
      2. BRouting is optional in production, so the hook is only a duplicate.
      3. CThe hook sees every call, so it catches limits crossed after intake.
      4. DRouting cannot read amounts.
      Show the answer

      Answer: C

      • A Hooks add a check. They do not speed up the model.
      • B Routing is not optional here. The point is a second layer for cases it cannot see.
      • C Correct. Intake sees the ticket once. The hook sees every tool call, so it catches limits crossed later.
      • D Routing can read amounts. The gap is what changes after intake.

      8. A refund hook denies a call because the customer is unverified. The next model turn calls process_refund again with the same arguments. What is the best design response?

      1. AGive the model unlimited attempts until it finally complies.
      2. BName the missing step in the denial and mark it retryable.
      3. CDisable the hook after two denials so the ticket can be finished.
      4. DEscalate every ticket that triggers any denial to a human.
      Show the answer

      Answer: B

      • A Repeated blind retries waste turns. The model needs to learn what to change.
      • B Correct. A clear, actionable denial lets the model call get_customer and then retry the refund.
      • C Turning the gate off after two denials defeats it.
      • D Escalating every denial floods humans with tickets the agent could finish.

      9. A team escalates any ticket where the customer sounds angry. Resolution rate is low and humans are overloaded. What is the flaw?

      1. ATone says nothing about whether the agent can solve it.
      2. BAnger detection is too slow to run during a live chat.
      3. CHumans cannot be expected to read angry messages all day.
      4. DThe model refuses to reply to customers who sound angry.
      Show the answer

      Answer: A

      • A Correct. A furious customer with a simple refund is well within the agent's ability. Sentiment is not complexity.
      • B Speed is not the issue. The signal is the wrong one.
      • C Humans handle angry messages every day. That is not the flaw.
      • D Models answer angry customers without trouble.

      10. Which two escalation triggers follow good practice? Select two.

      1. AA negative sentiment score above 0.7 on the last message.
      2. BAn over-limit refund or a policy exception.
      3. CThe customer writes in capital letters or uses several exclamation marks.
      4. DAn explicit request to speak to a person.

      Answer: B, D

      • A A sentiment threshold measures mood, not difficulty.
      • B Correct. Each trigger is explicit, testable and tied to a real limit of the agent.
      • C Typography says nothing about whether the agent can solve the ticket.
      • D Correct. A request for a person is honoured whatever the amount or the tone.

      11. A customer writes 'I want to speak to a real person.' The order is a simple $20 refund. What should the agent do?

      1. AComplete the refund first, then mention the option of talking to a person.
      2. BHand the ticket to a human, as the customer asked.
      3. CAsk the customer to explain why they want to talk to a person.
      4. DReply that the agent can handle it fully and carry on with the ticket.
      Show the answer

      Answer: B

      • A This overrides the request. The customer asked for a person, and honouring it is a rule.
      • B Correct. An explicit request for a human is a clear trigger, whatever the amount or tone.
      • C Interrogating the customer adds friction and delays the handoff.
      • D Insisting on continuing ignores an explicit request.

      12. You want to check that your escalation rule is not driven by tone. Which test best does that?

      1. ARun twenty calm tickets and confirm that none of them escalate.
      2. BCheck that the word angry appears in none of the code files.
      3. CAsk three teammates whether the rule feels fair to customers.
      4. DRun same-facts tickets in two tones and assert equal routing.
      Show the answer

      Answer: D

      • A Calm tickets alone do not show what happens when the tone changes.
      • B Words can hide in data or in a model call. Absence in code proves little.
      • C Opinions are not a test. The rule needs an assertion that can fail.
      • D Correct. Holding the facts fixed and changing only the tone isolates the variable the rule must ignore.

      A. The model fills in every tool argument, so an injected ticket can set the flag. A check must read state your code wrote, like state.verified_customer, never a claim inside the call.

      Conclusions

      • A rule in the prompt is a request. Code that runs before the tool is a guarantee.
      • A precondition check refuses with a category, a retry hint and a message, so the model can recover.
      • Escalate on amount, policy or an explicit request, never on tone.
