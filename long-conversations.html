      Two functions as written

      update returns the facts after one more turn. The starting code returns them unchanged, so no fact is ever kept. trim cuts a tool result to the fields that matter. The starting code returns the whole result.

      Each request carries a rolling window: a summary plus the last eight turns. A shipment result of 1,776 characters is paid for on every request while it stays in that window, and the case holds four of them.

      Facts are kept in code, output is trimmed

      update copies the customer, order, amount and approval date from the order lookup into the facts. Later turns do not erase them. trim keeps only the fields each tool is used for, and the tests need the result under a quarter of its size.

      Put the key facts at the start or the end of the context, under a heading. The middle of a long input is where detail is missed. None of this needs a model.

      The same rules run in the Agent SDK

      In the Claude Agent SDK, trim runs as a PostToolUse hook, code the SDK runs right after a tool returns. In this real Claude Haiku 5.5 run, the shipment result reaches Claude at 74 of 1,776 characters. With the starting code, Claude cannot give the amount or the date.

      Because a hook is plain code, it is deterministic. A rule that must hold before every refund goes in a PreToolUse hook on the refund tool, for example HookMatcher(matcher=REFUND, hooks=[check]).

      A session is one saved conversation, and session_extras picks how the next one starts: {"resume": id} replays the saved history, adding "fork_session": True copies it first, and {} starts fresh. Resume suits a session whose context is still true. Start fresh with a summary and the facts when it is stale, and tell a resumed agent which files changed.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A 30-turn refund case is summarised three times. On turn 31 the customer asks for the refund amount and the agent asks them again. What is the best fix?

      1. AKeep the amount and date in a facts block that code rebuilds and puts first.
      2. BSwitch to a model with a larger context window so the whole history fits.
      3. CWrite a longer summary prompt and ask the model to keep every number.
      4. DAsk the customer to repeat the amount at the start of each session.
      Show the answer

      Answer: A

      • A Correct. Code keeps the facts exactly, so no summary can rewrite them.
      • B A larger window holds more text but does not stop a summary from dropping the amount.
      • C A longer prompt still asks a summary to rewrite itself, and each rewrite blurs numbers again.
      • D This moves the work to the customer and leaves the agent unchanged.

      2. Each order lookup returns 40 fields and the agent uses 5. After four lookups, 85 percent of the context is tool output. What should change?

      1. ARaise the output token limit so the model can read the longer results.
      2. BTell the model in the prompt to ignore the extra fields.
      3. CSummarise the tool results once the window is nearly full.
      4. DCut each result to the five fields needed before the model reads it.
      Show the answer

      Answer: D

      • A The output limit controls the reply, and the results still fill the input.
      • B The ignored fields still cost tokens on every request.
      • C A late summary can blur the values the answer needs.
      • D Correct. Trimming keeps the needed fields and drops the rest, so every later turn is cheaper.

      3. A 60,000 token input holds two key findings in the middle. The model misses both and finds a third one at the top. What is the best change?

      1. APut the key findings first, under a clear heading.
      2. BShorten the sentences around the findings.
      3. CLeave them in the middle, because the model reads the whole input evenly.
      4. DRepeat the question twice at the end of the prompt.
      Show the answer

      Answer: A

      • A Correct. The start and the end of a long input are read most reliably, and a heading names what matters.
      • B Shorter sentences do not change where the findings sit.
      • C Attention is uneven across a long input, and the middle is where detail is most easily missed.
      • D The question is not the problem. The findings are hard to find.

      4. Select two effects of a history that grows to 30 turns of full tool output.

      1. AOld detail is buried, so a value from turn 3 is easy to miss.
      2. BThe model reads the old lines more carefully than the new ones.
      3. CEvery request carries the whole history, so cost rises each turn.
      4. DThe model reads the history once, so later turns cost nothing extra.
      Show the answer

      Answer: A, C

      • A Correct. The value is still there, but the model has more to search.
      • B Attention does not favour the old lines. Detail in the middle is easily missed.
      • C Correct. Each turn resends the history, so it is paid for again.
      • D Every request sends the history again, so the cost recurs on each turn.

      5. An investigation was left for two weeks, and most of the files it read have changed since. The agent resumes the named session and quotes the old results. What is the best handling?

      1. AResume and raise the turn limit so the agent has time to notice.
      2. BStart fresh with a summary and the facts, because the old context is stale.
      3. CResume again and trust the old results, since the session remembers the work.
      4. DFork the session so the stale results are copied into a safe branch.
      Show the answer

      Answer: B

      • A More turns do not tell the agent that the files changed.
      • B Correct. A fresh start with the facts drops the stale output.
      • C A resumed session carries the old results, which are now wrong.
      • D A fork copies the same stale history into the branch.

      6. A team wants to compare a refactor and a rewrite, both starting from the same 40-turn investigation. Which approach fits?

      1. AResume the same session twice and run both approaches in it.
      2. BStart two fresh sessions and paste a summary into each.
      3. CRun the refactor first, then the rewrite, in one session.
      4. DFork once per approach, so each branch starts from the same history.
      Show the answer

      Answer: D

      • A Both approaches would write into one history and mix their results.
      • B A fresh summary loses detail that the forks would keep.
      • C The rewrite would start from the refactor's results, not the original state.
      • D Correct. A fork copies the history into a new session, so each branch starts equal.

      7. A named session continues after two files changed. The agent still quotes the old file contents. What do you add when you resume?

      1. AA longer system prompt that says to trust the session.
      2. BNothing, because a resumed session refreshes its own files.
      3. CA line that tells the agent which files changed, so it reads them again.
      4. DA second fork of the same session.
      Show the answer

      Answer: C

      • A Trusting the session is what keeps the old results in use.
      • B A session holds what was read then. It does not watch files.
      • C Correct. The agent cannot see the change unless it is told, and it can read the two files again.
      • D A fork copies the same old results.

      8. Select two valid uses of resuming a named session.

      1. AContinue work after a large refactor changed most of the files.
      2. BContinue a task in the same session, where the context is current.
      3. CStart a follow-up on the same task the next morning, when no files changed.
      4. DBranch into two experiments from one saved point.
      Show the answer

      Answer: B, C

      • A After a large change the old results are stale, and a fresh start with a summary is safer.
      • B Correct. The context is still true, so resuming saves the work.
      • C Correct. Nothing changed, so the history is still accurate.
      • D Branching is a fork, which copies the history into a new session.

      9. A shipment tool returns dates in three formats. Downstream code parses 1 in 6 of them wrongly. What is the most reliable fix?

      1. ANormalise the dates in a PostToolUse hook, before the model reads the result.
      2. BTell the customer which format to expect.
      3. CRetry the tool until it returns a format the parser knows.
      4. DAsk the model in the prompt to rewrite each date before it uses it.
      Show the answer

      Answer: A

      • A Correct. A hook runs every time and reshapes the result before the model sees it.
      • B The customer did not choose the format.
      • C A retry returns the same mixed formats.
      • D A prompt is probable, not certain, and 1 in 6 misses would persist.

      10. A business rule must hold before any refund, with no exception. Which control fits?

      1. AA longer tool description that explains the rule.
      2. BA hook that checks the rule in code before the refund tool runs.
      3. CA sentence in the system prompt that states the rule.
      4. DA reviewer who reads the transcripts each week.
      Show the answer

      Answer: B

      • A A description guides the choice of tool and does not block a call.
      • B Correct. A hook is deterministic, so the rule holds on every call.
      • C A prompt rule is followed most of the time, and this rule needs every time.
      • D A weekly review finds a breach after the refund is paid.

      11. A prompt asks the model to trim its own tool output. In a test of 12 replies, 1 skips the trim. What is the best change?

      1. AReword the prompt to say trim in capital letters.
      2. BMove the trim into a PostToolUse hook that runs on each result.
      3. CAdd two examples of a trimmed result to the prompt.
      4. DLower the temperature and run the test again.
      Show the answer

      Answer: B

      • A Emphasis improves the odds but leaves a chance of a miss.
      • B Correct. A hook runs in code, so the trim does not depend on the model.
      • C Examples help, and the model can still skip the step.
      • D A lower temperature reduces variety and does not make a step certain.

      12. Select two things a PostToolUse hook can do.

      1. AChange what the model decided before it called the tool.
      2. BLog each result for later review.
      3. CReshape a tool result before the model reads it.
      4. DUndo a tool call that already finished.
      Show the answer

      Answer: B, C

      • A The call was already made. A PreToolUse hook acts before it.
      • B Correct. The hook sees the result, so it can record it.
      • C Correct. The hook can replace the output the model reads.
      • D The tool already ran. A hook cannot take that back.

      Conclusions

      • Case facts are kept in code, outside the summary, and placed first.
      • Each tool result is cut to the fields the next step needs.
      • Resume, fork or start fresh depends on whether the history is still worth its size.
