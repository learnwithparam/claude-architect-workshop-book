      Choose MCP, a direct API or agent-to-agent by who reuses it

      140 tools in every request

      The registry holds 140 tools, 7 actions for each of 20 areas. Thirty labelled requests fall into three kinds of need.

      Look-alike tools get mixed up

      A clear request is not the test. The same 140 tools also hold a get tool and a search tool for each area, and they read alike. So eight lookups, each worded as "Show me the invoice for order O-1007", went out with all 140 tools.

      In these eight runs, 8 of 8 called a look-alike tool. Six called a search tool where a get by id was meant, and two called the order tool for a refund or a warranty.

      Each request was 10,667 or 10,668 input tokens. The wording leaves the choice open, and a big list of near twins is where it goes wrong.

      Choose by reuse, discover by query

      choose maps a need to a mechanism. Another team's agent wins first. Then a need used by two or more teams gets MCP. The rest get a direct call. discover scores every tool against the request and returns the top 8.

      The arithmetic is plain. A request that carries 140 definitions bills about 10,700 input tokens. Across 10,000 calls a day that is about 107 million tokens. Eight definitions bill about 1,200 tokens, or about 12 million.

      When MCP earns its place

      A shared server serves many agents from one place. One owner keeps the tool current, and a fix reaches every agent. A one-off does not need that, and a server for it costs more than it returns.

      A server also holds the role's tool list. A tool outside that list cannot be called, whatever the prompt says. Enforce in managed settings and hooks shares settings across teams.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. Three teams at a shop each wrote their own order lookup for the support agent, and the 3 copies returned different fields last week. Each copy has its own owner and its own deploy. The lookup will be reused by a fourth team next month. Which integration fits a need that several teams reuse?

      1. ALet each team keep its copy and add a test that compares the outputs.
      2. BWrap the lookup in a prompt that every team pastes into its agent.
      3. CRun one shared MCP server for the lookup, with one owner.
      4. DPut the lookup in a shared document that agents read.
      Show the answer

      Answer: C

      • A A test that compares 3 copies finds drift after it happens. The lookup still exists 3 times and needs 3 fixes.
      • B A prompt describes a tool, and it does not run one. Each team would still need its own code behind it.
      • C Correct. A shared server serves every agent from one place, so a fix by its one owner reaches all 4 teams.
      • D A document cannot query an order. The agent needs a tool that returns the live record.

      2. An engineer needs one unit conversion, from kilograms to pounds, inside a single script that runs once a week. No other team has asked for it, and a shared MCP server would take about a week to build and host. The script already calls the Messages API. What is the sound mechanism?

      1. AStand up an MCP server, since every tool should be served that way.
      2. BHand the conversion to another team's agent and wait for its reply.
      3. CAvoid direct tools, since a direct call is the legacy way.
      4. DWrite the conversion as a direct tool in the script's own request.
      Show the answer

      Answer: D

      • A A server pays off when several agents reuse the tool. One script that runs once a week gains nothing from it.
      • B A call to another agent adds a round trip and a dependency for a sum the script can do itself.
      • C A direct tool is not legacy. It is the plain choice when one caller needs it and nobody else does.
      • D Correct. With no reuse, a direct tool in the request is the smallest thing that works.

      3. The refunds team already runs an agent that decides whether an order qualifies for a refund, with its own rules and its own tools. The support team needs the same decision for 30 tickets a day and must not copy the rules. The refunds team changes its rules every month. What should the support agent do?

      1. ACopy the refunds rules into the support prompt and update them monthly.
      2. BCall the refunds team's agent with the question and use its answer.
      3. CExpose each refunds tool to the support agent as its own tool.
      4. DAsk the refunds team for a list of rules each month.
      Show the answer

      Answer: B

      • A A copy drifts the month the refunds team changes a rule, and nobody is told.
      • B Correct. The other team's agent owns the decision, so a call to it keeps the rules in one place.
      • C That rebuilds the refunds logic in the support agent, with the rules spread across two teams.
      • D A monthly list is a copy that goes stale between one month and the next.

      4. A design review compares a shared MCP server with one direct tool per agent for a lookup that 5 agents will use. The server costs a week to build, and each direct copy costs a day. Select two reasons that favour the shared server.

      1. ASeveral agents reuse the tool from one place.
      2. BMCP is the newer way, so it is the better default.
      3. COne owner keeps the tool current for every agent.
      4. DA server makes the model call the tool more often.
      Show the answer

      Answer: A, C

      • A Correct. Reuse is the test, and 5 agents reusing one lookup pay back the week.
      • B Age is not a reason. A one-off tool gains nothing from a server, however new the protocol is.
      • C Correct. A fix made once by the owner reaches every agent, which 5 separate copies cannot do.
      • D The mechanism does not change how often the model picks a tool. The description does.

      5. Every request to a support agent carries 140 tool definitions, about 10,700 input tokens, because each team added its own. Cost per call is high and the agent sometimes picks a look-alike tool. The team needs a change that lowers both. What fits?

      1. AMerge the 140 tools into 20 tools with longer descriptions.
      2. BAsk the model in the prompt to ignore tools that do not apply.
      3. CDiscover a handful of tools by query and send only those.
      4. DMove the whole list to a larger model with a bigger window.
      Show the answer

      Answer: C

      • A Longer descriptions add tokens, and merged tools hide what each one does. The request is no lighter.
      • B The 140 definitions are still sent and still billed. A line asking the model to ignore them is a request.
      • C Correct. A request that carries 8 definitions costs about 1,200 tokens, and there are fewer look-alikes to confuse.
      • D A larger model reads the same 140 definitions at a higher price. The count is the cost.

      6. A support agent uses the same 12 tools on every request, and the set has not changed in 6 months. A proposal adds a discovery step that searches a registry before each call, which adds one round trip of about 300 ms. The prefix is large and stable. What is the better choice?

      1. AKeep the 12 tools in a cached prefix and skip the discovery step.
      2. BAdd discovery anyway, since a smaller request is lighter.
      3. CSplit the 12 tools across 3 agents at random.
      4. DDrop 6 tools to keep the set short.
      Show the answer

      Answer: A

      • A Correct. A small stable set is cheap when cached, and discovery would add a round trip for no saving.
      • B Discovery pays when the set is large or changing. For 12 stable tools it adds latency and a failure point.
      • C A random split breaks the set so some requests miss the tool they need.
      • D The agent uses all 12, so dropping 6 removes tools it needs.

      7. Tool choice accuracy fell from 96 percent to 81 percent after 30 tools were added with overlapping descriptions. Four tools all say they get an order. The team must restore accuracy this sprint without retraining anything. What should it do?

      1. AAdd a prompt rule that says to pick the most specific tool.
      2. BRaise the temperature so the model explores the list.
      3. CAdd 30 more tools so each case has its own.
      4. DTrim the overlap and discover a few tools per request.
      Show the answer

      Answer: D

      • A A rule cannot separate tools whose descriptions say the same thing. The model still sees four twins.
      • B A higher temperature makes choices less steady, not more accurate.
      • C More tools add more look-alikes, and the choice gets harder.
      • D Correct. Fewer and clearer tools in each request remove the confusion at its source.

      8. A cost review looks at an agent that sends all 140 tool definitions on each of 10,000 requests a day. The review asks what sending every tool costs. Select two costs of doing so.

      1. AMore input tokens on every call.
      2. BA lower chance of a cache hit on the answer text.
      3. CMore look-alike tools for the model to confuse.
      4. DA longer output, since the model lists each tool.
      Show the answer

      Answer: A, C

      • A Correct. 140 definitions come to about 10,700 tokens, and they are billed on each of the 10,000 calls.
      • B The answer text is not cached by its tools. The cost of the tools shows up in input tokens.
      • C Correct. Near-identical descriptions make a wrong pick more likely as the list grows.
      • D The model writes one tool call, not a list of the tools it skipped.

      9. A nightly job runs 3 steps in a fixed order for each order, which are fetch the record, check the stock and write a label. The steps never change and each takes under a second. A teammate proposes an agent that decides the order of the 3 tools. What is the better design?

      1. AAn agent, since it adapts to new cases.
      2. BA workflow that calls the 3 tools in code, in order.
      3. CA coordinator agent with 3 sub-agents, one per step.
      4. DAn agent with all 3 tools and a prompt that lists the order.
      Show the answer

      Answer: B

      • A The steps are known, so the agent adds cost and variance and leaves the order to the model.
      • B Correct. When the path is fixed, code is the workflow, and it runs the same way on every order.
      • C A coordinator and 3 sub-agents add calls and latency to 3 fixed steps.
      • D A prompt that lists the order is a request, and the model can skip or reorder a step.

      10. A support agent gets 2,000 different requests a week, and the tool that serves each one depends on the words in it. The steps cannot be fixed in advance, and the registry holds 140 tools. The team wants the model to choose at run time, inside a sensible bound. What fits?

      1. AHard-code 2,000 branches in the workflow, one per request.
      2. BSend all 140 tools and let the model search them.
      3. CLet the model pick from a small set discovered for each request.
      4. DRoute every request to a human, who picks the tool.
      Show the answer

      Answer: C

      • A Two thousand branches cannot cover next week's requests, and each one needs an owner.
      • B A full list costs about 10,700 tokens on each call and crowds the choice with look-alikes.
      • C Correct. The path depends on the input, so the model chooses, and discovery bounds the list it chooses from.
      • D A human on every request removes the point of the agent and cannot keep up with 2,000 a week.

      11. One shared MCP server serves the support role and the billing role. Support may read and update records, while billing may read and refund. A delete tool exists on the server, and the team wants the support role to be unable to call delete or refund. Where is that set?

      1. AIn the role's tool list at the server, so the other tools are not offered.
      2. BIn a prompt line that tells the support agent to avoid delete.
      3. CIn a log alert that fires when support calls refund.
      4. DIn the client, by hiding delete from the support dashboard.
      Show the answer

      Answer: A

      • A Correct. A tool outside the role's list at the server cannot be called, whatever the client or the prompt says.
      • B A prompt line is a request. A model can be argued out of it.
      • C An alert fires after the refund has been paid, so it reports the harm and does not stop it.
      • D A dashboard is a view for people. The agent's list at the server is unchanged.

      12. A discovery step returns 8 tools for a request, and one of them, refunds_update, is not on the caller's role list. The model asks for it, and logs show this happened 3 times this week. The team wants the call to fail with no change to how discovery ranks. Where should it be refused?

      1. AIn the prompt, with a line that lists the tools the caller may use.
      2. BIn the discovery ranking, by scoring the tool lower.
      3. CIn a weekly review of the 3 calls.
      4. DAt the server, which checks the caller's list on each call.
      Show the answer

      Answer: D

      • A The model can still ask for a tool that is not on the list, and a sentence cannot refuse the call.
      • B A lower score changes the order of the list and does not remove the tool. It can still be returned.
      • C A review after the call finds the change after it was made.
      • D Correct. The server holds the role's list and refuses any call outside it, in code the model cannot skip.

      Play: predict the output

      This discovery step ranks tools by the words they share with the request.

      python
      def discover(query: str, top: int = 8) -> list[Json]:
    q = set(query.lower().split())
    ranked = sorted(
        REGISTRY,
        key=lambda t: -len(q & set(t["description"].lower().split())),
    )
    return ranked[:top]

      Conclusions

      • Choose the mechanism by who reuses the tool: MCP for shared, a direct call for one caller, an agent call for another team's decision.
      • Send the few tools a request needs, found by query, and not the whole registry.
      • Refuse a tool outside the role's list at the server, in code, and not in the prompt.
