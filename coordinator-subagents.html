      Coordinator and subagents

      One coordinator spawns focused researchers together

      A team asks Claude for a recall report on a faulty power bank. The coordinator plans only the cause and the scope, so customers and the regulator are never researched. It also starts one researcher per turn, so the report is slow and incomplete. This is the agent at Lumen Supply, an online electronics shop. You will watch one coordinator miss angles and wait, then fix it with a plan and a brief.

      I doWatch the failure and its fix.

      A coordinator plans the angles and researchers cover them

      The coordinator does not research. It splits the topic into angles that together cover the whole report, briefs one researcher for each, and merges what comes back. The plan lists the angles, the model spawns and merges, and the Agent SDK runs the subagents.

      This design fails in three ways. The split is too narrow, the researchers run one per turn, and the subagents get steps instead of goals. You will see the first two fail, then fix them.

      The coordinator runs the same agent loop as in An agent is a loop that ends on stop_reason. Claude picks the next tool, each result joins the history, and the loop continues on tool_use and stops on end_turn. A turn cap is only a safety net, never the stop rule.

      Cover the whole topic, then spawn together

      The fix has two parts. plan lists an angle for each concern the report must answer. brief tells the coordinator to spawn every researcher in the same response. It also tells the coordinator to name any angle with no findings.

      The brief also gives each researcher a goal, not a script of steps. A subagent starts fresh: it sees none of the coordinator's turns, so the goal and the fact it must return are all it learns about the task. Independent angles have no reason to wait.

      Angles must not overlap. If two researchers repeat the same queries, divide the topic so each owns one question. Ask each subagent a specific question, and keep the coordination in the main agent. When the merged findings hold an empty section, have the coordinator send a new task for that angle.

      Researchers in the Agent SDK

      A researcher is a subagent defined by a description, a prompt and a tool list. The coordinator starts it with the Agent tool, so that tool must be allowed. The notice sender and the web search go in disallowed_tools, so not even the coordinator can call them.

      The harness runs the request through the SDK's query() and counts the researchers spawned in each response. This is a real Claude Haiku 5.5 run.

      In a long investigation the early findings scroll far back. A scratchpad is a plain file the agent writes findings to and rereads on resume. fork_session branches a resumed session to try another approach. Keep noisy discovery in a subagent, and after a crash resume from saved state.

      1. A recall report for a power bank has sections on the cause and the scope but nothing on the regulator. The coordinator's plan listed two angles, and each got a researcher. What is the root fix?

      1. AAdd a line saying the regulator is out of scope, since both researchers finished.
      2. BChange the plan so its angles cover the whole topic, including customers and the regulator.
      3. CTell the writer to sound more confident in the regulator section.
      4. DGive each researcher 10 more search turns.

      Answer: B

      • A Both researchers finishing shows only that the two angles were covered. The report still lacks what it must answer.
      • B Correct. An angle nobody owns is never researched, so the gap starts in the plan.
      • C Confident wording cannot add a finding that no researcher produced.
      • D More turns deepen the two angles. They do not create a third or a fourth.

      2. Two researchers repeat the same search: 40 percent of their queries overlap. Their angles are both worded as 'the power bank' plus a verb. What fixes the overlap?

      1. ARun them one at a time so the second can skip what the first found.
      2. BRaise the search limit so both researchers can finish every query they start without being cut off.
      3. CUse one researcher for all four angles so nothing repeats.
      4. DDivide the topic into angles that do not overlap, each with its own question.
      Show the answer

      Answer: D

      • A A researcher starts fresh and never sees what the first one found, so it cannot skip anything. The wait only adds seconds.
      • B A higher limit lets both repeat more. The overlap is in the split.
      • C One researcher loses the parallel speed and still needs the angles defined.
      • D Correct. Distinct angles give each researcher different work, so the repeated queries disappear.

      24. Select two facts about what drives an agentic loop.

      1. AThe code picks the next tool from a fixed list.
      2. BThe model picks the next tool from the history.
      3. CThe history is cleared after every tool call.
      4. DEach tool result joins the history before the next model call.
      Show the answer

      Answer: B, D

      • A A fixed list is a script, not a loop.
      • B Correct. Choosing the next step is the model's part of the loop.
      • C A cleared history would lose every result.
      • D Correct. That is how the model sees what its call did.
