      Prompt techniques

      Add a technique only for the failure it fixes

      A Lumen Supply team adds chain-of-thought to a prompt whose real fault is its output format. The replies get longer and cost nearly five times as much, and none of them parses. This lesson matches each of four failures to the one technique that fixes it, and shows what the wrong ones cost. The Lumen support assistant makes four kinds of mistake. Its triage reply does not parse, its refund sums are wrong, its tone breaks the house rules, and it sends a ticket to the wrong queue. You will run four techniques on each, read the score and the cost, and write the table that picks.

      I doWatch the failure and its fix.

      One prompt, four different failures

      A technique is one block added to a prompt: a step-by-step instruction, worked examples, an output schema, or a rubric. The model follows the prompt, and your code scores the reply, so a fix is real only when the score moves.

      Three things go wrong, in this order. Chain-of-thought is used for a format fault, so cost rises and the format still breaks. Examples are missing where the format is the issue. And no table maps a failure to its technique, so each fix is a guess.

      Match the technique to the failure

      pick reads a table from each failure to one technique. It raises an error for a failure it does not know. build_prompt is the same in both files, so only the choice of technique changed.

      A task with several steps is split into separate prompts, one technique each. A checked contract sits between them, so a failure belongs to one step. An order that must hold is enforced in code, and the prompt only asks for each step.

      The cost of a wrong choice is paid on every call. Chain-of-thought adds about 250 output tokens per ticket for a fault it cannot fix, and 10,000 tickets a month make that $12.55 more than the schema.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A triage step must return JSON that a parser reads, and about 1 call in 6 returns text the parser rejects. The team added chain-of-thought last week, replies grew 40 percent in tokens, and the failure rate did not change. The cost cap is fixed, and the parser cannot change. What should the team do?

      1. AAsk for even more careful step-by-step reasoning, since the model is not thinking enough yet.
      2. BAdd three more sentences to the instruction that tell the model to be careful about the JSON.
      3. CRaise max_tokens so the long replies are no longer cut off before the JSON closes.
      4. DAdd a schema with the exact keys and values, and drop the chain-of-thought.
      Show the answer

      Answer: D

      • A More thinking adds tokens and cost, and the reply still has to be parsed. The fault is the form, not the logic.
      • B Longer instructions are still prose. They do not give the model a form to copy, so the rate stays near 1 in 6.
      • C A cut-off reply is one cause, but the replies grew because of the added reasoning, and the cap is fixed.
      • D Correct. A format fault needs a form the model can copy. Without the reasoning, the replies shrink and the cost falls.

      2. A refund step returns the answer in the right form every time. But 1 call in 4 gets the arithmetic wrong on orders with a discount and a restocking fee. The cost cap is tight, and the other four steps of the pipeline already pass their scores. Which change fits?

      1. AAdd chain-of-thought to every step of the pipeline, so none of them can fail later on.
      2. BAdd stepwise reasoning to the refund step only, then re-score it on the same orders.
      3. CAdd a schema for the answer line, since a wrong number is a problem with the form.
      4. DAdd two worked examples of a refund that show the final amounts and no working.
      Show the answer

      Answer: B

      • A The other steps already pass. Reasoning tokens on them are cost with no score change.
      • B Correct. Logic faults need working before the answer, and only the failing step pays for it.
      • C The form is already right. A schema cannot make the arithmetic correct.
      • D Examples with bare amounts show the form, not how to get the number, so the sums still go wrong.

      3. A prompt review finds that a team added a new technique to a support prompt last sprint. The review must decide whether the technique was chosen for a named failure or only because it is popular. It has the golden-set scores and the cost per call from before and after. Select two signs that it was added without a matching failure.

      1. AThe failing cases went from 4 of 6 to 6 of 6 after the change, on the failure it named.
      2. BCost per call rose and the score on the golden set did not change.
      3. CThe reply got longer, and the review reads that as the prompt being more thorough.
      4. DNobody wrote down which failure the technique was meant to fix.
      Show the answer

      Answer: B, D

      • A This is the opposite sign. A named failure and a score that moves are what a matching technique has.
      • B Correct. A technique that adds tokens and moves no score is paying for nothing.
      • C Length is not quality. Longer replies cost more and say nothing about whether the fault is fixed.
      • D Correct. Without a named failure there is nothing to match, so the choice is a guess.

      4. A parser reads each reply as JSON and rejects about 1 in 6. One teammate wants chain-of-thought added and another wants a schema, and replies must parse on the first try while the token cost per call does not grow. Select two reasons that favor the schema over chain-of-thought.

      1. AThe schema gives the reply a form to copy, with named keys and allowed values.
      2. BA schema makes the model think harder before it answers, so the JSON comes out cleaner.
      3. CChain-of-thought puts working before the JSON, and that text costs output tokens on every call.
      4. DA schema works only when worked examples are added to it, so the two have to travel together.
      Show the answer

      Answer: A, C

      • A Correct. A schema is a form the reply can copy, and it adds few tokens.
      • B A schema adds no thinking. It fixes the form, which is a different fault from the logic.
      • C Correct. Reasoning before the reply puts prose ahead of the JSON, which breaks the parse and adds tokens.
      • D A schema is one block that works alone. In the recorded runs it scored 3 of 3 with no examples.

      5. A team splits a refund task into steps by writing one prompt with a numbered list of six steps. The steps depend on each other, a late step fails about 1 call in 5, and nobody can tell which step produced the bad output. Each step needs its own check. What is the better design?

      1. AMake the list longer, with more detail for each of the six steps in the same prompt.
      2. BAsk the model to repeat each step number before it answers, so that the order is visible.
      3. CSeparate steps, each with its own prompt and a contract for its input and output.
      4. DRun the same prompt three times and take the most common reply as the answer.
      Show the answer

      Answer: C

      • A More detail in one prompt makes the single call harder to check, and a failure is still not tied to a step.
      • B Repeated numbers show an order but do not check any step's output.
      • C Correct. Each step gets the technique its failure needs, and its output is checked before the next step runs.
      • D Voting costs three times as much and hides which step is wrong.

      6. A numbered list in a prompt says to check the order, then the refund limit, then send the reply. In production the model sometimes sends the reply before checking the limit, 1 call in 30. The order of the steps is a hard requirement, and a wrong send cannot be undone. What fixes this?

      1. ACode enforces the order, and the prompt only asks for each step.
      2. BWrite the list in capital letters so that the order is stressed to the model.
      3. CAdd chain-of-thought so the model thinks about the order of the steps first.
      4. DAdd two worked examples that follow the list in the right order every time.
      Show the answer

      Answer: A

      • A Correct. A rule that must hold is enforced in code, so the send cannot run before the check passes.
      • B Emphasis is still a request. A prompt cannot guarantee that a step ran first.
      • C Thinking about the order makes the model more likely to follow it, but not certain, and it adds cost.
      • D Examples raise the odds and still leave 1 call in 30 that does not follow them.

      Conclusions

      • Name the failure first, then add the one technique that fixes it.
      • A schema fixes a format, steps fix reasoning, a rubric fixes tone and worked examples fix routing.
      • Read the score and the cost together: a technique that adds tokens and moves no score is a bad bet.

      You can now map a failure to its technique, build the prompt for it, and prove with a score that the fix worked.

      Technique

      One block added to a prompt, such as steps, examples, a schema or a rubric

      Chain-of-thought

      An instruction to work through the problem before the final answer

      Schema

      The exact form of the reply: its keys and allowed values

      Worked examples

      Sample inputs with the reply you want, shown in the prompt

      Rubric

      A checklist of house rules the reply must meet

      Failure

      The way a reply goes wrong, named before a fix is chosen
