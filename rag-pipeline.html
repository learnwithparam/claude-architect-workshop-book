      Chunk and search, written as code

      Two functions hold the design. The file shown is the starting one. A page has id, title, text, topic, version and access. chunk should split at the headings and keep version (as doc_version), access and topic on every piece.

      search should route an order id to an exact lookup and drop what the caller may not read. Then it should blend keyword and vector scores.

      Retrieval is measured on its own before any answer is judged. The test asks whether the right page is among the top 3 for each of the 60 queries. When answers drop after a model upgrade and a re-index in the same week, read that number first: if it fell, the index changed what the model saw.

      Shape the chunks, filter, then blend

      chunk splits at the headings, so the limits table stays whole. Each chunk keeps doc_version and access, which is what the filters read.

      search sends an order id to an exact lookup, and that finds O-48214 alone. For everything else it drops the pages the caller may not read and the retired versions. Then it blends a keyword score and a vector score and keeps only the strong matches.

      Keywords catch exact codes such as RFD-7714 that vectors blur. A real embedding also catches paraphrases that keywords miss. This lab's vector is a bag of words, so search keeps a chunk only when it shares at least one keyword with the question. Overlapping the 500-character pieces does not help either, because a label can still part from its value.

      The index fix is written once and runs on every question. A hosted vector database is warranted only when measured recall at 3 falls short at your size; a small index that meets the goal is enough.

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A policy assistant indexes 24 policy pages, and each policy exists in 3 versions. A customer was told the refund window is 14 days, which is the text of the retired version 1, while the current page says 30 days. The team wants the answer to come from the current page only, with no change to the prompt. What should retrieval do?

      1. AAsk the model in the prompt to prefer whichever page shows the latest date in its own text.
      2. BRe-embed every page with a larger embedding model so the versions separate better.
      3. CKeep only the newest page by its file name in the answer text, and cite that file.
      4. DKeep doc_version on each chunk and return only the newest version.
      Show the answer

      Answer: D

      • A The model cannot tell which page is current, and a date in the text is not a version. Retrieval has to decide.
      • B A better embedding ranks the three versions as near twins, because they read almost the same. The version is a fact about the page, not about its meaning.
      • C A name in the answer text is read after the model has already used the page. The filter has to run before it.
      • D Correct. The version travels on each chunk, so search can drop the retired ones before the model reads anything.

      2. A refund page is split into 500-character pieces, and its limits table starts at character 461. The row that holds the 30 day window is cut in two, so the label lands apart from the value. Answers about limits are wrong in 9 of 20 test questions. Which change fixes the cause?

      1. ARaise the piece size to 800 characters and test again on the same twenty questions.
      2. BSplit each page at its headings, so the limits table stays whole.
      3. COverlap the pieces by 100 characters so that both halves appear together in a result.
      4. DAsk the model to rebuild the table from the two halves it is given in the prompt.
      Show the answer

      Answer: B

      • A A different size moves the cut to a different row. Some other page is now cut in some other place.
      • B Correct. The page has a shape, and a heading is where its meaning breaks. A chunk per heading keeps the table whole.
      • C An overlap repeats part of the text but can still leave a label apart from its value, and it costs extra tokens.
      • D The model can only work with the halves it is given, and it may fill the gap with a guess.

      3. A customer asked which extension reaches fraud operations, and the assistant returned it from a staff-only page. The system prompt already says to share nothing marked staff. There are 6 staff pages among 40, and the team wants a guarantee that an outside caller never reads one. What provides it?

      1. AAdd the word staff to a list of banned words that the reply is scanned for.
      2. BTell the model twice in the prompt that the staff pages are private and must stay hidden.
      3. CFilter the chunks by the caller's access before the model sees any.
      4. DAsk the model to reply only with the public facts from the page it is given.
      Show the answer

      Answer: C

      • A A word list on the reply runs after the model has read the page, and the extension number is not the word staff.
      • B The page is already in the model's context. A request not to share it is a request, and the model can lose it.
      • C Correct. A chunk the caller may not read is dropped before the prompt is built, so the model has nothing to leak.
      • D The model would have to decide what is private. The decision belongs to the access list, in code.

      4. An audit of a retrieval index with 40 documents finds that a search result carries only the page title and its text. The team must add fields so that a search can drop retired pages and private pages before the model reads them. Select two fields to keep on every chunk.

      1. AHow often the page was opened last month, so that popular pages win.
      2. BThe document's version number.
      3. CThe chunk's position within its page, counted from the top.
      4. DThe access list of the document.
      Show the answer

      Answer: B, D

      • A Popularity says nothing about which page is current or who may read it. A retired page can be the most opened.
      • B Correct. With the version on the chunk, a filter can keep the newest page and drop the retired ones.
      • C A position says where the text sat in its page. It says nothing about which page is current or who may read it.
      • D Correct. With the access list on the chunk, a filter can drop a private page for an outside caller.

      5. A customer asks where order O-48214 is. Vector search returns order pages O-48216, O-48218 and O-48211, because every five-digit number looks alike to it, and the assistant says it cannot find the order. The team is considering a larger model for the answer step. What fixes the fault?

      1. ADetect the order pattern and look the page up by its exact id.
      2. BSend the top 10 pages instead of the top 3 so the right one is likely among them.
      3. CUpgrade the answer step to a larger model that reads the passages more carefully.
      4. DRe-embed the order pages with more vector dimensions so that the ids separate.
      Show the answer

      Answer: A

      • A Correct. An identifier is an exact string, so an exact lookup finds the page that the vectors could not rank first.
      • B Ten near matches still may not hold the right page, and the model has more noise to read.
      • C A larger model reasons better about what it is given, and it was given the wrong order pages. The fault is upstream.
      • D More dimensions still count a digit string by its shape, so neighbouring ids stay close and the same pages win.

      6. In a test of 60 labelled queries, keyword search finds the right page for 38 and misses paraphrases. Vector search finds 41 and misses exact codes such as RFD-7714, and neither passes 80 percent. The team wants one route for the ordinary questions. Which design fits?

      1. ARun keyword search first and use vectors only when it finds nothing at all.
      2. BBlend the keyword score and the vector score and rank by the sum.
      3. CTrain a new embedding model on the 60 queries and use it alone for every question.
      4. DLet the model choose between the two result lists on each question it answers.
      Show the answer

      Answer: B

      • A A keyword hit that is wrong blocks the vector route, so the paraphrase case is still lost.
      • B Correct. A page that both routes like rises above one that only one route likes, and the blend covers both misses.
      • C Training on the 60 test queries proves nothing, because the score is measured on the same data.
      • D The model would need both lists in its prompt, and it cannot tell which list holds the current page.

      7. A team proposes a hosted vector database for 3,000 support pages, and the quote adds 120 ms to each search and a new service to operate. A keyword index and a small in-process vector index already reach 95 percent recall at 3 on the 60 labelled queries. What is the sound decision?

      1. ABuy the database now, because a corpus only grows and moving later costs more.
      2. BDrop the keyword index, because vectors cover the same ground at a lower cost.
      3. CMove to the database and keep the old index as a second copy for safety.
      4. DKeep the small index, and measure again if recall falls.
      Show the answer

      Answer: D

      • A A plan for growth is not a measured fault. Recall is 95 percent today, and the service adds cost and a failure point.
      • B Vectors miss exact codes and ids, which is the reason the keyword route was added.
      • C Two copies need two syncs, and either can go stale, which is a new fault for no measured gain.
      • D Correct. The measured recall meets the goal at this size, so the simpler index wins until a number says otherwise.

      References

      • Citations: tie each answer to the chunk it came from.
      • Embeddings: vector search, and where it ties on near-identical text.
      • Contextual retrieval: keyword and vector search together, with context on each chunk.
      • Create strong empirical evaluations: the labelled queries recall is measured on.

      Conclusions

      • Chunk by the shape of the page, and keep the version and access list on each chunk.
      • Route an exact identifier to an exact lookup, and blend keyword and vector scores for the rest.
      • Filter by version and access before the model sees a passage, then check retrieval on its own.

      You can now shape an index so the current, permitted page is what the model reads and cites.

      Chunk

      One piece of a page that is indexed and returned

      Recall at k

      The share of queries whose right page is in the top k

      Exact lookup

      Finding a page by its identifier, with no ranking

      Hybrid search

      A blend of keyword and vector scores

      Access filter

      A check that drops pages the caller may not read
