      Orchestration patterns

      Match the pattern to the task, and write every seam down

      Lumen Supply moved its support reports to a team of agents to go faster. The run cost more and was no quicker, and two workers returned shapes the next step could not read. This lesson picks the pattern by the shape of the task. This is the analytics desk at Lumen Supply, an online electronics shop. You will run four tasks, each with its own pattern, then write the rule that chooses one and the contract at every seam.

      I doWatch the failure and its fix.

      One desk, four shapes of work

      Orchestrator-workers, sectioning, voting and evaluator-optimizer each fit one shape. In orchestrator-workers the model splits the work. In the other three, the code splits it.

      A seam is the point where one step hands its output to the next, such as a worker's answer going to the merge. The code owns each seam and checks what crosses it. The team owns the budget.

      Three things go wrong. A linear task is split across workers. A seam has no contract, so workers return shapes nobody can read. A loop has no cap.

      Check your understanding
      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.
      

      1. A weekly report has four sections, and no section reads another. It must be ready in 20 seconds, with each worker call taking about 8, and one call can write only about 500 words against the 2,000 needed. The cost cap allows four calls and one merge. How should you build it?
      1. ARun one worker for the whole report, then a checker that reviews the finished text for quality.
      2. BPut all four sections in one prompt and ask for one long answer, then trim the result to fit.
      3. CRun the four sections as parallel workers, then merge their findings.
      4. DRun the four sections in order, each worker reading the finished text of the one before it.
      Show the answer
      Answer: C
      • A One worker takes the sections one by one, so it will not fit the 20 seconds, and it cannot write 2,000 words. A checker adds one more call.
      • B One prompt is one call, not a split. It hits the 500 word cap, gives no seam to check and no parallel speedup.
      • C Correct. Independent parts are sectioning. The four calls overlap, so the run takes about one call's time.
      • D Running in order makes the time four calls long, about 32 seconds. The sections do not need each other.
      2. A compliance check asks one yes or no question about a message, such as whether it leaks a card number, and a wrong answer is costly. The budget allows three calls per message. A single call is right 9 times in 10, and the errors look random. How do you raise confidence in one decision?
      1. AAsk the same question three times and take the majority answer.
      2. BAsk three differently worded questions, each leaning toward a yes, and count the yes answers.
      3. CSplit the message into three parts and send one part to each call, then combine the three answers.
      4. DAdd three more workers that each write a longer explanation of why the message is safe or not.
      Show the answer
      Answer: A
      • A Correct. Voting repeats one check and takes the majority, which cuts the chance of a one-off error.
      • B Different wording changes the question, and a lean toward yes biases every vote. Votes are comparable only on the same prompt.
      • C A part of a message may miss the card number that sits in another part. This is sectioning, and it does not vote.
      • D Longer explanations are not votes. Nothing gets counted, and the answer is no more certain.
      3. An analyst asks why ticket volume rose last month, and nobody knows how many causes there are. The subtopics only appear once the data is read, so two workers may be enough, or six. The budget is a flat 10 calls for the request. Which pattern fits it?
      1. AOne prompt that lists every cause the team has seen before and asks the model for each one.
      2. BSix fixed workers, one per cause the team thought of last year, each reading the same data.
      3. CWorkers that return free text, joined by the next step exactly as it arrives.
      4. DAn orchestrator that splits at run time, then workers on each part.
      Show the answer
      Answer: D
      • A A fixed list in one prompt cannot name causes that the data has not shown yet.
      • B A fixed count of workers assumes the split is known. It wastes calls when there are two causes.
      • C Free text at the seam is the failure. Joining whatever comes back breaks on the first odd shape.
      • D Correct. The split is open, so the orchestrator decides it at run time and hands each part to a worker.
      4. A team is choosing where an evaluator and drafter loop fits, with a hard spend limit and one more call for each pass. The draft is a product blurb that must meet a score the code can compute. Which conditions make a task fit this pattern? Select two.
      1. AThe draft can be scored by a clear rule that the code checks.
      2. BA good draft is worth any number of turns, so the loop needs no cap.
      3. CThe checker's reasons name what to change, so a second draft can fix it.
      4. DOne prompt can carry the draft, the rubric and the retries together.
      Show the answer
      Answer: A, C
      • A Correct. A checkable rubric gives the loop a test that does not depend on the drafter's opinion.
      • B A loop with no cap has no end if the rubric is never met, and the spend limit is hard.
      • C Correct. Reasons the drafter can act on make each turn better than the last, which is what pays for the loop.
      • D One prompt has no checker outside the model and no loop in code. It is not this pattern.
      5. Two workers feed a merge step. On 1 run in 4 the merge fails, because one worker returns a sentence and the other returns a JSON object. The prompts were reviewed twice and are fine, and the model version is unchanged since the failures began. What is the fix?
      1. ARewrite the merge step so it tries to read whatever shape it receives from each worker.
      2. BWrite an input and output contract for the seam, and refuse output that does not fit.
      3. CMerge the two workers into one prompt so the two outputs can no longer differ in shape.
      4. DAdd a third worker to read both outputs, decide which is right and pass that one on.
      Show the answer
      Answer: B
      • A A merge that accepts any shape hides the fault. It fails later, somewhere harder to see.
      • B Correct. The contract names the keys, and the code refuses a bad output at the seam where it is made.
      • C This drops the split and its speed. The seam still exists between the prompt and the next step.
      • D A third worker adds a seam with no contract, and a third place for the shape to differ.
      6. A five-step pipeline passes each output straight to the next step. A bad output at step 2 surfaces as a wrong answer at step 4, two steps later. Engineers lose hours finding where it began, and the retry budget is one rerun per request. Where should the check go?
      1. AAt step 4, where the wrong answer first shows, because that is where it hurts the user.
      2. BAt the start, in a longer prompt that tells every step to be careful with its output.
      3. CAt every seam, so a bad output is refused at the step that made it.
      4. DAt the end, with a retry of the whole pipeline until the final answer passes.
      Show the answer
      Answer: C
      • A Step 4 only sees the symptom. The fault is two steps upstream, and the error points at the wrong step.
      • B A prompt asks the model to be careful. Only code at the seam can refuse an output.
      • C Correct. A check at each seam stops the fault where it starts and names the step that owns it.
      • D Retrying the whole pipeline pays for five steps each time and does not say where it broke.
      7. An evaluator and drafter loop has no stop rule. One night it ran 14 turns on a blurb whose rubric could not be met, and the cost rose each turn. The team wants the worst case bounded before the next nightly run, without losing the good drafts. What should be added?
      1. AA turn budget, and a stop rule on the score so the loop ends when it passes.
      2. BA turn count of 40 instead of 14, so the loop has more time to meet the rubric.
      3. CA second drafter, so two drafts are tried in each turn and the better one is kept.
      4. DA rule that the checker may skip its reasons on later turns to save tokens.
      Show the answer
      Answer: A
      • A Correct. A cap ends the loop when the score is never met, and a stop rule ends it when it is.
      • B More turns raise the worst case. A rubric that cannot be met will still run out the budget.
      • C Two drafters double the cost of each turn, and the loop still has no end.
      • D Without reasons the drafter has nothing to fix, so the loop is less likely to converge.
      8. A multi-agent design with three workers and one merge is under audit, and the reviewer asks what a decomposition must state at each seam. The audit is written down, and each answer must be something a test can check. What must each seam name? Select two.
      1. AThe model name that each worker runs on, so a run can be repeated.
      2. BThe input schema that the worker receives.
      3. CA note that the next step will work out the shape from the text it gets.
      4. DThe output schema that the next step reads.
      Show the answer
      Answer: B, D
      • A The model is a setting of the worker. It says nothing about what crosses the seam.
      • B Correct. The input schema says what the worker is given, so a wrong input is refused.
      • C A shape left to the next step is the missing contract, and it is where the merge fails.
      • D Correct. The output schema is what the next step reads, so a bad output is refused where it was made.
      9. A team built a five-step task as a multi-agent system to go faster, and each step needs the output of the one before. The cost tripled and the time did not fall. The steps cannot change order, and each step still needs its own check. What should it have been?
      1. AFive workers run in parallel, with a longer timeout on each one so none is cut off.
      2. BFive workers run in parallel, merged by one more worker at the end of the run.
      3. COne prompt with the five steps numbered, run as a single long call with no seams.
      4. DA workflow that runs the steps in order, each reading the last output.
      Show the answer
      Answer: D
      • A Parallel workers cannot start a step before its input exists. A longer timeout only waits longer.
      • B A merge after parallel workers still cannot run dependent steps together, and it adds a call.
      • C A numbered prompt drops the seams, so no step can be checked or retried alone.
      • D Correct. Dependent steps are a chain. Order is the only thing they need, so no split is worth its cost.
      10. A support bot answers one question per message by reading one help article, and it needs no steps after that. A teammate proposes an orchestrator with three workers. Latency is 2 seconds now, the budget is flat, and answers are already correct. What is the right call?
      1. ABuild the orchestrator, because a team of workers is more reliable than a single call.
      2. BKeep the single call that reads the article, the lowest complexity that works.
      3. CBuild it, but run the three workers in parallel so the latency holds at 2 seconds.
      4. DSplit the article into three parts and have one worker read each part in order.
      Show the answer
      Answer: B
      • A More workers add seams and cost. Reliability comes from a check at the seam, not from headcount.
      • B Correct. One call with retrieval answers a single question. Step up only when that fails.
      • C Parallel workers still add calls and a merge to a job that one call already does.
      • D Reading parts in order adds steps with nothing to decide, and it slows a 2 second answer.
