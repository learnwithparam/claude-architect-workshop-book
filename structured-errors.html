      Structured tool errors

      A tool error should say what to do next

      Your refund tool fails with the single word Error. The agent cannot tell a timeout from a refusal, so it retries a refusal and then guesses at a reason for the customer. This is the agent at Lumen Supply, an online electronics shop. You will watch it fail, then fix it with two small functions.

      I doWatch the failure and its fix.

      Every failure has a category and a flag

      Three parties share the work. The tool reports the failure. The harness, the code around Claude that runs each tool, decides whether to retry. Claude explains the result to the customer.

      A refund can fail four ways: transient, validation, permission or business. A timeout is transient and a wrong order id is validation. Another customer's order is permission, and a closed refund window is business.

      Each failure needs two answers. What kind is it, and can a retry help? The tool reports both, so the harness never guesses from a sentence.

      A category and a flag replace the word Error

      fail now sets isError and carries errorCategory, isRetryable and the message. Only a transient failure is retryable. should_retry reads the flag, so a timeout is retried and a refusal is not.

      The harness bounds the retries and waits a short random time between them. Any transient fault gets the same bounded retry.

      The same tool runs in the Agent SDK

      The Claude Agent SDK serves the refund and the lookup from an in-process MCP server. The Python SDK spells the failure flag is_error, as the API does.

      Here Claude decides whether to retry, so the error shape is all it has. That is why the prompt asks for one retry, a line the harness above never needs. This is a real Claude Haiku 5.5 run. With the starting code the reply blames a system error, and with structured errors it explains the refund window.

      A subagent is a second agent that a coordinator starts for one job. It should retry a transient fault locally and pass up only what it cannot fix, with the partial results. Two mistakes to avoid: returning an empty result as if it worked, and aborting all four subagents because one failed. This is the report a coordinator receives:

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A refund tool returns the text "Error" for every failure. The agent retries an order that is past the refund window and then guesses at a reason. What is the best fix?

      1. AAdd a long prompt paragraph that lists every reason a refund can fail and what to say for each.
      2. BRaise the retry limit so the agent has more chances to find the cause.
      3. CReturn an error with a category, a retryable flag and a message the agent can read.
      4. DLog the failure on the server and return an empty result so the agent moves on.
      Show the answer

      Answer: C

      • A A prompt cannot know which reason applied to this call. The tool knows.
      • B More retries repeat a refusal that no retry can change.
      • C Correct. The category and the flag tell the harness whether a retry can help, and the message tells Claude what to say.
      • D An empty result hides the failure, and the agent has nothing to explain.

      2. Which failure should the harness retry without asking Claude?

      1. AA refund request for an order that is 239 days old.
      2. BA refund request for an order id written with a letter in it.
      3. CA refund request for an order that belongs to another customer.
      4. DA payment service that timed out once.
      Show the answer

      Answer: D

      • A This is a business refusal. Trying again gives the same answer.
      • B This is a validation error. The input has to change first.
      • C This is a permission error. A retry does not change the owner.
      • D Correct. A timeout is transient, so the same call may succeed a moment later.

      3. Which fields make a tool error useful to both the harness and Claude? Select two.

      1. AA stack trace from the server that raised it.
      2. BAn error category such as transient, validation, permission or business.
      3. CThe HTTP status code alone, such as 500, used as the whole category.
      4. DA retryable flag the harness can read without parsing text.
      Show the answer

      Answer: B, D

      • A A stack trace is operator detail. A customer never needs it.
      • B Correct. The category says what kind of failure it is, so each kind gets the right response.
      • C A status code says where a call failed, not what to do next. A 500 can be a timeout or a bug.
      • D Correct. The harness decides on the flag, not on a guess from a sentence.

      4. A tool fails because the customer gave an order id that matches no order. Which category fits, and what follows?

      1. ATransient, so the harness retries the same call again.
      2. BValidation, so Claude asks for a corrected id.
      3. CPermission, so Claude asks the customer for a manager.
      4. DBusiness, so Claude explains the refund window to them.
      Show the answer

      Answer: B

      • A The same id fails again. Only a transient failure earns a retry.
      • B Correct. The input is wrong, so the next step is a corrected input.
      • C Nothing was denied. The order was not found.
      • D The refund window is not the problem. The id never matched an order.

      5. A lookup returns an empty list for a customer with no orders. The agent calls it three times and then says the lookup failed. What is the right handling?

      1. AReturn the empty list, no error flag, and say nothing was found.
      2. BRaise the retry limit to five, in case the orders load on a later try.
      3. CReturn an error flag on an empty list, so the agent stops asking.
      4. DDrop the result and ask the customer to try again later.
      Show the answer

      Answer: A

      • A Correct. Nothing found is a valid answer. An access failure is different, and it carries an error.
      • B The list is empty because the customer has no orders, so five tries return the same list.
      • C An error flag says the call failed. This one worked and found nothing.
      • D The customer learns nothing, and the real answer is lost.

      6. Where should retries of a transient failure live?

      1. AIn the system prompt, as a rule for Claude to follow.
      2. BIn a background job that replays every failed call until one succeeds.
      3. CIn code around the tool call, bounded by the retryable flag.
      4. DIn the tool description, as a sentence that tells Claude to try the call twice.
      Show the answer

      Answer: C

      • A A prompt rule depends on Claude counting attempts. Code counts exactly.
      • B Replays with no bound hammer a tool that refuses. A retry needs a limit and a flag.
      • C Correct. Code can bound the attempts and stop on a refusal.
      • D A description says what a tool does. It cannot enforce a limit.

      7. A refund fails with a permission error because the order belongs to another customer. Which reply is best?

      1. AApologise, say something went wrong, and ask them to try again later.
      2. BSay the refund cannot be done on that order, and offer to look up their own orders.
      3. CSay who owns the order, so they can contact that person and sort it out between them.
      4. DClose the ticket at once, because the first failed call ends the conversation.
      Show the answer

      Answer: B

      • A This hides the reason, and a later try gets the same refusal.
      • B Correct. It refuses plainly and offers a next step that stays within their account.
      • C Naming the owner leaks another customer's data.
      • D One refusal does not end the ticket. The customer still needs a reason and a next step.

      8. A coordinator runs four subagents and one fails. Select two mistakes in how the failure is handled.

      1. AThe subagent swallows a timeout and returns an empty result as if it had worked.
      2. BThe reply names what failed, what was tried, and what the customer can do next.
      3. CThe subagent retries a timeout once, and passes up only what it could not fix.
      4. DThe coordinator aborts the whole run because one of four subagents failed.
      Show the answer

      Answer: A, D

      • A Correct. The coordinator now trusts a result that is not real.
      • B This is what a good failure report contains.
      • C A local retry of a transient fault is good practice. Only what it cannot fix goes up.
      • D Correct. Three good results are lost, and the failed one could have been reported as partial.

      Play: spot the bug

      The retry rule is right, but the harness hands it the wrong thing.

    result = lookup_order("1042")

      Predict: The lookup times out, and its error says isRetryable is true. Is it retried?

      1. AYes. The error says a retry can help.
      2. BNo. The flag sits inside result["error"], so the rule reads nothing and says no.
      Show the answer

      B. The rule reads isRetryable from the top of what it gets, and the flag is one level down. Pass result["error"], and test the harness with a real failure, not only the rule alone.

      Conclusions

      • A tool failure carries a category, a retryable flag and a readable message.
      • Only a transient failure is retried, in code, with a bound.
      • An empty result is a valid answer, not an error.
      • Claude explains a refusal in plain words and leaves out operator detail.

      You can now build tool errors that tell the harness whether to retry and tell Claude what to say.

      Error category

      The kind of failure: transient, validation, permission or business

      Retryable flag

      A field that says whether the same call may succeed later

      Transient error

      A temporary fault, such as a timeout, that a retry can clear

      Empty result

      Nothing found, reported with no error flag

      Business error

      A refusal by a rule, such as a closed refund window
