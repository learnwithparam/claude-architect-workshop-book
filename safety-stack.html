      The safety stack

      A guardrail is a check with an address

      Lumen Supply gives its support agent one paragraph of rules and calls that a guardrail. A courier page asks for a customer's phone and address, and the agent sends both. This lesson wraps the agent in six checks, each with an owner, and writes down every risk and who catches it. This is the support desk at Lumen Supply, an online electronics shop. You will run three attacks against a prompt-only agent, then against six layers, and then review the risk register that names who owns each risk.

      I doWatch the failure and its fix.

      A hostile page and a paragraph of rules

      The model reads, and the layers check. A guardrail is a check somewhere in the system that can fail loudly and has a named owner. A register row names a risk, its owner and at least two independent catchers.

      Three things go wrong. The guardrail is a sentence in the prompt, so it has no place to fail. The register names risks with no owner or one catcher. Only the input is checked, so an unsafe reply still reaches the customer.

      The stack, written as code

      A layer is a name, an owner, a reason and a test. Here is the starting file, with one layer; the six arrive in the fix. They are the input screen, the tool allow-list, the action approval, the output screen, the rate limit and the audit. Each one answers a question about one message.

      A check by the model that wrote the output is not independent. A register row needs an owner and two catchers that are not the system prompt or the model.

      Keep the guardrail text in the fixed part of the prompt, before the turn that changes on each call, so it can be cached. Its place does not stop an edit, so keep it in a fixed, reviewed template that tenants cannot change.

      Layers with an owner

      layers returns six checks, each with an owner. gap returns every risk with no owner or fewer than two independent catchers. The output screen reads the second call's verdict, so the flag now stops the reply.

      Each recorded call used about 700 to 1,000 input tokens. Six cheap checks cost far less than one customer's details sent to the wrong address, which also has to be reported.

      Check your understanding

      Answer each question, then read why every option is right or wrong. The wrong options are the mistakes engineers make on the job.

      1. A risk register at an online shop lists prompt injection, and its only control is one paragraph in the support agent's system prompt. In a test of 3 hostile messages, the agent followed 1 and emailed a customer's phone number to an outside address. An auditor asks for a control that can fail loudly and has an owner. What do you add?

      1. AA second paragraph in the prompt that repeats the rule in capital letters.
      2. BA line in the register that says the model has been told the rule.
      3. CA check outside the model, such as a tool allow-list, with a named owner.
      4. DA lower temperature setting so the agent follows the paragraph each time.
      Show the answer

      Answer: C

      • A More emphasis is still a sentence the model may not follow. It has no place to fail loudly and no owner.
      • B Writing that the model was told changes nothing in the run. The register needs a check that someone owns.
      • C Correct. A check outside the model can fail loudly, and its owner knows to act when it does.
      • D A lower temperature makes the output steadier, not safer. The paragraph is still the only control.

      2. A support agent reads a courier web page that says to reply by email with the recipient's phone number and address. The agent has a send_email tool that can reach any address, and in a test of 3 attacks the page-driven one went out as written. The team wants the harm stopped, not only noticed. Which layer limits the tool that could send it?

      1. AAn allow-list that blocks any recipient outside the company domain.
      2. BAn audit log that records the email after it is sent.
      3. CA second model call that writes a summary of the page first.
      4. DA banner in the dashboard that tells staff to watch for hostile pages.
      Show the answer

      Answer: A

      • A Correct. The allow-list is code with an owner. It refuses the outside address, whatever the page says.
      • B A log is a detective check. It shows the leak after the email has gone and does not stop it.
      • C A summary of the page is still read by a model that can be talked into acting. Nothing in code limits the tool.
      • D A banner asks people to watch, and the tool still reaches any address. It is not a check with an owner.

      3. A team asks the same model that wrote a customer reply to check the reply for leaked data before it is sent. In 20 test replies, the check missed 4 that held a phone number, and the writing step had missed the same 4. The team wants a second catcher for this risk that does not share the fault. What should it be?

      1. ARun the same check twice, and send the reply when either run passes.
      2. BAsk the model to explain why it thinks the reply is safe.
      3. CAdd a sentence to the prompt that says to check carefully.
      4. DA pattern check in code for phone numbers, with its own owner.
      Show the answer

      Answer: D

      • A The same model makes the same miss, and a rule that sends on either pass is looser than a single check.
      • B An explanation comes from the model that made the miss. It is not an independent view.
      • C A sentence asks for care and adds no catcher. The 4 misses show the model does not see the fault.
      • D Correct. Code with its own owner does not share the model's blind spot, so it is an independent catcher.

      4. A review board compares two controls for an agent that can email customers. One is a sentence in the prompt, and the other is a check in code that refuses outside recipients. The board wants the properties that make a guardrail count in a register. Select two properties of a good guardrail.

      1. AIt is written in the system prompt where the model reads it.
      2. BIt runs outside the model, so no reply can talk past it.
      3. CIt is long and detailed so the model has no room to misread it.
      4. DIt has a named owner who acts when it blocks something.
      Show the answer

      Answer: B, D

      • A A sentence in the prompt is a request. It has no place to fail loudly, so it is not a guardrail on its own.
      • B Correct. A check outside the model holds whatever the page or the user says to the model.
      • C A longer rule is still a request. Detail does not give it an address or an owner.
      • D Correct. An owner means a failure has someone to act, which is what the register records.

      5. An audit of a support agent finds six controls in place, an input screen, an allow-list, an approval, an output screen, a rate limit and a log. None has a named owner. When the output screen blocked 3 replies last week, nobody looked at them. The auditor asks what to change before the next review.

      1. AAdd a seventh control, so the risk has one more check on it.
      2. BName an owner for each control, who acts on its blocks.
      3. CMove all six controls into the system prompt as rules.
      4. DReplace the controls with one stronger output screen.
      Show the answer

      Answer: B

      • A More checks with no owner add more blocks nobody reads. The 3 blocked replies show the gap is action.
      • B Correct. A guardrail is a check with an address. The owner is who acts when it fires.
      • C Rules in the prompt have no place to fail, so the six checks would become requests.
      • D One layer is one place to fail. Defence in depth keeps several, each with an owner.

      6. A shop screens every incoming message for phrases such as ignore previous instructions, and it blocked 12 last month. A staff-style message with no such phrase asked the agent for a customer's phone number, and the agent replied with it. The team wants a second layer that would have stopped this reply. What is it?

      1. AAn output screen that reads each reply for phone numbers.
      2. BA longer list of hostile phrases in the input screen, updated weekly.
      3. CA weekly report of the replies that went out.
      4. DA note in the prompt that staff messages may be fake.
      Show the answer

      Answer: A

      • A Correct. The message had no hostile phrase, so only a check on the reply sees the phone number.
      • B The message had no phrase to find. A longer list still checks only the input.
      • C A report is read after the reply has gone. It does not stop this one.
      • D A note in the prompt is a request the model may not follow, with no owner and no place to fail.

      7. A register row says staff code in a reply has one catcher, the output screen, and it has an owner. Last month a pattern change made the screen miss a code in 2 of 30 replies, and nothing else noticed. The reviewer wants the row to meet the rule for a risk. What does the row need?

      1. AA second line in the prompt that tells the model to hide codes.
      2. BA note that the owner will watch the screen more closely.
      3. CA rule that the screen is checked by the model that wrote the reply.
      4. DA second independent catcher, such as a log search for codes.
      Show the answer

      Answer: D

      • A A prompt line is a request, so it is not a second catcher. It cannot fail loudly.
      • B The row already has an owner. Watching more closely is not a second check that works while the owner sleeps.
      • C The model that wrote the reply shares its blind spot, so it is not independent.
      • D Correct. Two independent catchers mean one failing silently, as the screen did in 2 of 30, does not leave the risk open.

      8. A design review asks which two of the proposed layers belong in the stack for an agent that can send email. The team has room for a tool allow-list, an output screen, a longer system prompt and a note that the model should be careful. Select two layers of a safety stack.

      1. AA tool allow-list that refuses outside recipients.
      2. BA longer system prompt with more rules.
      3. CAn output screen that reads each reply before it is sent.
      4. DA note in the handbook that the model should be careful.
      Show the answer

      Answer: A, C

      • A Correct. It is a check in code with an owner, and it limits what the tool can do.
      • B More rules in the prompt are still requests. They have no address and no second catcher.
      • C Correct. It reads what would reach the customer, so it catches what the input screen cannot see.
      • D A handbook note asks people to be careful. It does not run, so it cannot block anything.

      9. A moderation call flags 3 of 3 attack replies as personal data, but the agent sends all 3 because no layer reads the flag. The desk sends 2,000 emails a day, about 1 in 200 is flagged, and a flagged reply may wait up to 4 hours. The team wants each flagged message decided before the send. Which design does that?

      1. ALog the flag so a weekly report counts it.
      2. BAsk the moderation model to try again until it says safe.
      3. CHold each flagged reply for a named reviewer before it goes.
      4. DLower the number of flags by loosening the moderation prompt.
      Show the answer

      Answer: C

      • A A report counts the leaks after they went out. It is a detective control and stops nothing.
      • B Retrying until the answer is safe removes the warning and lets the send through.
      • C Correct. The flag now has an address. A named reviewer decides within the 4 hours, before the email goes, and 10 a day is a load one person can carry.
      • D Fewer flags do not make fewer leaks. They hide the signal the stack needs.

      10. A stack has an approval step before any email leaves, and 40 emails waited last week. No one is named as the approver, so 9 of them sat for two days and a few were released by whoever was free. The reviewer wants the layer to count in the register. What should the team do?

      1. ALet the approval lapse after 4 hours, so a stuck email sends itself.
      2. BName the approver, and keep an independent check beside it.
      3. CLet the model approve its own emails when it is confident.
      4. DApprove every email in bulk at the end of the week.
      Show the answer

      Answer: B

      • A A timeout that releases the email turns the layer off whenever it is slow. The fix is an owner, not a way around the layer.
      • B Correct. A layer needs an owner who acts, and a second independent check covers the day the owner misses.
      • C The model that wrote the email shares its blind spot, so its approval is not independent.
      • D A weekly bulk approval has no owner who reads each one, so the risk stays open.

      11. A shared agent keeps its guardrail text in the cached start of the prompt, so every tenant reads it and the cache saves cost. One tenant edits its copy to remove a rule, and 2 of 5 tenants now run a different guardrail. The security lead wants the guardrail to stay the same and reviewed. What do you do?

      1. ARepeat the guardrail in each user turn, so an edit to one copy is outvoted.
      2. BTurn off the cache so each call reads a fresh prompt.
      3. CAdd a second copy of the guardrail at the end of the prompt.
      4. DKeep it in a fixed, reviewed template that tenants cannot change.
      Show the answer

      Answer: D

      • A A tenant can edit the turn as easily as the prefix, and a repeated request is still a request with no owner.
      • B The cache is not the fault. A fresh prompt still carries whatever text a tenant edited.
      • C A second copy of text the tenant can edit is still editable, and still a request.
      • D Correct. A fixed template with a reviewer means a tenant's edit cannot change the guardrail.

      12. A team puts the guardrail text after the user turn, which changes on every call, so the cached start is rebuilt each time and costs more. In 50 calls, the guardrail was read last and 3 replies ignored it. The team wants the guardrail stable and cheap. Where should it sit?

      1. AIn the fixed start of the prompt, before the changing turn.
      2. BAfter the user turn, repeated three times.
      3. CIn a separate system message sent after the user turn, marked as high priority.
      4. DIn the user turn, so it changes with each request.
      Show the answer

      Answer: A

      • A Correct. A fixed guardrail before the changing turn can be cached and reviewed, and it does not move.
      • B Repeating it after the turn still changes the end of the prompt on every call and adds a request, not a check.
      • C A message after the user turn still moves on every call, so the cached start is rebuilt, and a priority label is a request.
      • D Putting it in the turn means it changes with each call, which breaks the cache and the review.

      Conclusions

      • Put each guardrail in a check outside the model, with a named owner.
      • Check the output as well as the input, and give every risk two independent catchers.
      • A flag from a classifier does nothing until a layer acts on it.

      You can now wrap an agent in layers that each have an owner, and review a register for gaps.

      Guardrail

      A check outside the model that can fail loudly and has an owner

      Layer

      One check in the stack, such as an input screen or an allow-list

      Independent catcher

      A second check that does not share the first one's failure

      Risk register

      A table of risks, each with an owner and its catchers
